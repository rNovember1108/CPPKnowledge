# 线程与异步任务

C++ 提供了多种异步编程的机制，从底层的线程（`std::thread`）到高层的异步任务接口（`std::async`），甚至 C++20 的协程。

## 线程

通过创建并使用 `std::thread` 的方式异步执行 `doAsyncWork()` 函数，这是**基于线程（thread-based）**的策略。

### 线程使用

C++11 引入了 `std::thread` 类简化线程创建，`std::thread` 的构造函数接受任意可调用对象（Callable）。下面分别演示用全局函数、类的成员函数、Lambda 表达式来创建线程。

#### 全局函数

最直接的用法，直接把函数名和参数传给 `std::thread` 的构造函数。

```cpp
void global_function(int a, const int& b)
{
    std::cout << "Global function executing, address:" << &a << ", " << &b << std::endl;
}

int main()
{
    int a = 1, b = 4;

    // 创建并启动线程
    std::thread t(global_function, a, b);

    // 等待线程结束
    t.join();

    std::cout << "main function executing, address:" << &a << ", " << &b << std::endl;
    return 0;
}
```

参数是按**衰减拷贝（decay-copy）**存储到线程内部的：`std::thread` 会对每个参数做 `std::decay_t` 处理，即移除引用、数组退化为指针、函数退化为函数指针。因此即使原参数是引用，也会退化成普通值再拷贝一份。要真正传引用，需要用 `std::ref`——它生成一个 `std::reference_wrapper`，再把这个包装器按值拷贝进去，从而在调用时还原成引用。

```cpp
void global_function(int a, const int& b)
{
    std::cout << "Global function executing, address:" << &a << ", " << &b << std::endl;
}

int main()
{
    int a = 1, b = 4;

    // 创建并启动线程
    std::thread t(global_function, a, std::ref(b)); // 必须用 std::ref 传引用，否则会按值拷贝

    // 等待线程结束
    t.join();

    std::cout << "main function executing, address:" << &a << ", " << &b << std::endl;
    return 0;
}
```

#### 类的成员函数

成员函数比普通函数多一个隐含的 `this` 指针，所以第一个参数必须传对象指针或对象本身。

```cpp
class Worker
{
public:
    void member_function(int id)
    {
        std::cout << "成员函数线程: id=" << id << ", 对象地址: " << this << std::endl;
    }

    void const_member_function(int id) const
    {
        std::cout << "const成员函数线程: id=" << id << ", 对象地址: " << this << std::endl;
    }
};

int main()
{
    Worker w;

    // 传对象指针
    std::thread t1(&Worker::member_function, &w, 1);
    t1.join();

    // 传对象副本（会拷贝一份，注意区别）
    std::thread t2(&Worker::member_function, w, 2);
    t2.join();

    // const 成员函数一样
    std::thread t3(&Worker::const_member_function, &w, 3);
    t3.join();

    return 0;
}
```

1. `&Worker::member_function` 是成员函数指针，必须搭配对象才能调用。
2. 传 `&w`（指针）和传 `w`（拷贝）效果不同。如果对象是不可拷贝的（如含有 `std::mutex`），就只能传指针，或着配合 `std::ref` 传引用。

#### Lambda 表达式

最灵活的方式，C++11 之后最常用。适合需要捕获外部变量或写临时逻辑的场景。

```cpp
int main()
{
    // 按值捕获
    int x = 10;
    std::thread t1([x] {
        std::cout << "按值捕获: " << x << std::endl;
        });
    t1.join();

    // 按引用捕获（注意生命周期）
    int y = 20;
    std::thread t2([&y] {
        y += 5;
        std::cout << "按引用捕获: " << y << std::endl;
        });
    t2.join();
    std::cout << "y 最终 = " << y << std::endl;  // 25

    // 带参数的 lambda
    std::thread t3([](int a, int b) {
        std::cout << "带参 lambda: " << a + b << std::endl;
        }, 3, 4);
    t3.join();

    // 移动捕获（C++14）：把独占资源 move 进线程
    auto ptr = std::make_unique<int>(99);
    std::thread t4([p = std::move(ptr)] {
        std::cout << "移动捕获: " << *p << std::endl;
        });

    t4.join();

    return 0;
}
```

引用捕获存在致命的陷阱，如果线程还没执行完，被引用的变量就析构了，会引发悬垂引用。要么保证变量生命周期长于线程，要么在 `join()` 前不要让它离开作用域。

```cpp
// 危险示例
std::thread badThread;
{
    int local = 5;
    badThread = std::thread([&local] {
        std::this_thread::sleep_for(std::chrono::seconds(1));
        std::cout << local;  // local 可能已销毁！
    });
}  // local 析构
badThread.join();  // 未定义行为
```

### 线程注意事项

1. 必须 `join()` 或 `detach()`，线程对象析构时如果 `joinable()` 为 `true`，析构时会调用 `std::terminate()`，程序直接崩溃。这是为了防止线程在后台悄悄运行而资源无人回收，或者程序在不知情的情况下退出。为了确保线程对象被正确析构，推荐使用 RAII 包装或者 C++20 的 `std::jthread`（其会自动 `join()`）。

    ① `join()`：等待线程结束。其会阻塞当前线程，直到目标线程执行完毕，然后回收其资源。调用后，`std::thread` 对象不再关联任何线程，`joinable()` 变为 `false`。`join()` 只能对 `joinable()` 为 `true` 的线程调用，否则会抛出 `std::system_error` 异常。同时，一个线程只能被 `join()` 一次。

    ② `detach()`：分离线程，让其独立运行。`detach()` 将线程与 `std::thread` 对象解绑，线程转为后台运行（守护线程）。调用后，`std::thread` 对象不再关联该线程，`joinable()` 变为 `false`，线程的资源会在其执行完毕后由运行时库自动回收。分离后的线程若访问了已经销毁的局部变量或对象，会导致未定义行为。因此 `detach()` 通常只用于生命周期与程序相当、或完全自包含的任务。

    ③ `joinable()`：判断线程是否可管理（`join()` 或 `detach()`）。返回一个 `bool`，表示当前 `std::thread` 对象是否关联着一个正在执行或尚未被回收的线程。

2. 参数默认按**衰减拷贝（decay-copy）**存储：引用被移除、数组/函数退化为指针。若想传引用一定用 `std::ref`（本质是拷贝一个 `std::reference_wrapper`），否则修改的是副本。

3. 线程函数中抛出的异常若未捕获，会直接调用 `std::terminate()`，程序直接崩溃。

    ```cpp
    std::thread t([] {
        try
        {
            // 可能抛异常的逻辑
        }
        catch (...)
        {
            // 必须在线程内处理
        }
    });
    ```

4. 创建即启动，`std::thread` 构造完成就立即开始执行，没有"延迟启动"选项。

## 异步任务（std::async）

将 `doAsyncWork()` 函数传递给 `std::async()` 异步执行，这是**基于任务（task-based）**的策略。

### 基本用法

`std::async` 与 `std::future` 是 C++11 引入的高层异步接口，推荐用于"任务级"异步。

```cpp
int test(int x)
{
    return x * x;
}

int main()
{
    // 启动异步任务
    std::future<int> fut = std::async(std::launch::async, test, 10);

    // 阻塞等待并获取结果
    int result = fut.get();
    std::cout << result << std::endl;

    return 0;
}
```

### 启动策略

当你调用 `std::async()` 来执行函数（或其他可调用对象）时，通常是希望异步执行。但如果你对 `std::async()` 函数的启动策略指定不清晰，实际运用过程中可能不会按照你预期的结果发生。`std::async()` 有两种标准启动策略，通过 `std::launch` 这个限域 `enum class` 的一个枚举值表示。假定现有一个函数 `f()` 需要传给 `std::async()` 来执行，将根据指定的启动策略出现不同的情形：

1. `std::launch::async` 启动策略：意味着 `f()` 强制在新线程中异步执行。

    ```cpp
    // 立即开启新线程执行函数
    auto future = std::async(std::launch::async, f);
    
    // 阻塞等待函数返回结果
    int ret = future.get();
    ```

2. `std::launch::deferred` 启动策略：意味着 `f()` 延迟执行，直到调用 `get()/wait()` 时才在当前线程同步执行。这表示 `f()` 推迟到存在这样的调用时才执行，这将不创建新线程。

    ```cpp
    // 创建延迟任务，这里不会启动新线程
    auto future = std::async(std::launch::deferred, f);
    
    //调用future.get()时，才会去调用f(),通过打印线程ID可以看出，f()是在主线程中执行的
    int ret = future.get();
    ```

3. 除了上述两种标准启动策略之外，`std::async()` 还重载了一个不需要手动指定启动策略的函数版本。查看源码可知，它使用的启动策略是 `std::launch::async | std::launch::deferred`，默认策略，由实现选择。

    ```cpp
    // 用默认启动策略运行f()
    auto future1 = std::async(f);

    // 使用async或者deferred运行f()
    auto future2 = std::async(std::launch::async | std::launch::deferred, f);
    ```

    > 重要陷阱：默认策略下，如果系统资源紧张，可能退化为 `deferred`，导致你以为的"异步"实际是同步的。需要真异步时务必显式指定 `std::launch::async`。

### 返回值获取

`std::async()` 函数返回一个 `std::future` 对象，该对象可以用于获取异步任务的结果。其主要成员函数有：

1. `future.get()`：只能调用一次，会阻塞直到结果就绪，之后 `future` 失效。
2. `future.wait()`：只等待，不取值。
3. `future.wait_for(duration)`：超时等待，返回 `std::future_status`，有三种状态：`ready`（异步操作已经完成）/`timeout`（异步操作等待超时）/`deferred`（异步操作还没开始）。

    ```cpp
    int test(int x)
    {
        // 休眠 2 秒
        std::this_thread::sleep_for(std::chrono::seconds(2));
        return x * x;
    }

    int main()
    {
        auto future = std::async(std::launch::async, test, 10);
        if (future.wait_for(std::chrono::seconds(1)) == std::future_status::timeout)
        {
            std::cout << "wait for future timeout" << std::endl;
        }

        return 0;
    }
    ```

### 异常传播

`std::async()` 中抛出的异常会被捕获并存入 `std::future`，在 `get()` 时重新抛出。

```cpp
auto future = std::async(std::launch::async, [] {
    throw std::runtime_error("有异常啦");
    });

try
{
    future.get();
}
catch (const std::exception& e)
{
    std::cout << e.what() << std::endl;
}
```

### 析构行为

由 `std::async()` 以 `std::launch::async` 启动的任务，其 `std::future` 在析构时会阻塞，直到任务完成。

```cpp
int test(int x)
{
    std::cout << "test函数开始" << std::endl;
    std::this_thread::sleep_for(std::chrono::seconds(2)); // 休眠2S
    std::cout << "test函数结束" << std::endl;
    return x * x;
}

int main()
{
    {
        auto future = std::async(std::launch::async, test, 10);  // 添加作用域 future析构
    }

    std::cout << "main函数结束" << std::endl;
    return 0;
}
```

### std::promise 与 std::packaged_task

`std::promise` 和 `std::packaged_task` 都是 C++11 中用来把结果传递给 `std::future` 的设施，但它们的抽象层次和使用场景不同。理解它们的关键是看清各自谁负责产生结果。

两者都持有一个共享状态，都能通过 `get_future()` 拿到对应的 `std::future`，都支持 `set_value` / `set_exception` 语义，结果都能被 `future::get()` 获取。

#### std::promise 手动设置结果

`std::promise` 是一个纯粹的结果容器。你负责在某个时刻、某个线程里显式设置值或异常，它本身不执行任何逻辑。

```cpp
int test(int x, int y)
{
    if (y == 0)
    {
        throw std::runtime_error("除0异常");
    }
    return x / y;
}

int main()
{
    std::promise<int> prom;
    std::future<int> fut = prom.get_future();

    std::thread t([&prom] {
        try
        {
            int result = test(10, 0);
            prom.set_value(result);
        }
        catch (...)
        {
            prom.set_exception(std::current_exception());
        }
        });

    try
    {
        int v = fut.get();
        std::cout << "value: " << v << std::endl;
    }
    catch (const std::exception& e)
    {
        // 捕获所有标准异常，包括 future_error、runtime_error 等
        std::cout << "catch: " << e.what() << std::endl;
    }
    catch (...)
    {
        std::cout << "catch unknown exception" << std::endl;
    }

    t.join();

    return 0;
}
```

1. 不绑定任何可调用对象，设置结果的时机完全由你控制。
2. 只能设置一次，重复设置会抛 `std::future_error`，`set_value` 和 `set_exception` 是同一个结果槽的两种写法，无论哪种，都只能设置一次。
3. 如果不设置值就析构，共享状态里会存入 `std::future_error`（broken promise），`future::get()` 会抛出。
4. 适合结果在某个回调、信号处理器或异步事件中产生的场景，因为你可以把 `std::promise` 传来传去，在任意地方设置。

#### std::packaged_task 包装可调用对象

`std::packaged_task` 把一个可调用对象和一个 `std::future` 绑在一起。当你调用这个 task 时，它会执行可调用对象，并自动把返回值或异常填入共享状态。

```cpp
int test(int x, int y)
{
    if (y == 0)
    {
        throw std::runtime_error("除0异常");
    }
    return x / y;
}

int main()
{
    std::packaged_task<int(int, int)> task(test);
    std::future<int> fut = task.get_future();

    std::thread t(std::move(task), 10, 2);  // 在新线程执行
    try
    {
        int v = fut.get();
        std::cout << "value: " << v << std::endl;
    }
    catch (const std::exception& e)
    {
        // 捕获所有标准异常，包括 future_error、runtime_error 等
        std::cout << "catch: " << e.what() << std::endl;
    }
    catch (...)
    {
        std::cout << "catch unknown exception" << std::endl;
    }

    t.join();
    return 0;
}
```

1. 绑定可调用对象，调用它时自动设置结果，与 `std::promise` 不同，不需要手动调用 `set_value` / `set_exception`。
2. 可调用对象可以是函数、Lambda、函数对象，签名由模板参数指定。
3. 只可移动，不可拷贝（因为持有 `std::future` 的共享状态和可调用对象）。
4. 适合把任务本身作为一等对象传递，比如放进线程池的任务队列。

### std::future 与 std::shared_future

`std::future` 有两个关键限制：

1. 不可拷贝，只可移动。因此无法把它复制给多个线程。
2. `get()` 只能调用一次。第一次 `get()` 会消费掉共享状态，之后调用是未定义行为。

这导致了一个`std::future` 无法直接解决的经典问题：那就是**一个异步任务的结果，需要被多个消费者线程读取**，而 `std::shared_future` 解决了这两点：它可以拷贝，且每个副本都可以多次调用 `get()`，所有副本共享同一个结果。

`std::shared_future` 可以由 `std::future` 通过自带的 `share()` 函数或者移动构造（`std::move()`）得到。不过转换之后原来的 `fut` 不再关联共享状态，`fut.valid()` 为 `false`。

```cpp
std::future<int> fut = std::async(std::launch::async, [] {
    return 42;
    });

// 通过 share() 转换为 shared_future（fut 此后不再有效）
std::shared_future<int> sfut = fut.share();

// 通过移动构造 std::move 转换为 shared_future，同样可以
// std::shared_future<int> sfut = std::move(fut);

// 拷贝给多个线程
std::thread t1([sfut] { std::cout << "t1: " << sfut.get() << std::endl; });
t1.join();

std::thread t2([sfut] { std::cout << "t2: " << sfut.get() << std::endl; });
t2.join();

// 主线程也可以再次 get()
std::cout << "main: " << sfut.get() << std::endl;
```

`std::shared_future` 还可以用 `std::promise` 和 `std::packaged_task` 直接构造，`std::shared_future` 有一个接受 `std::future&&` 的移动构造函数，而 `prom.get_future()` 和 `task.get_future()` 返回的正好是一个临时对象（右值）。

```cpp
std::promise<std::string> prom;
std::shared_future<std::string> sfut = prom.get_future();

std::packaged_task<int(int, int)> task(test);
std::shared_future<std::string> sfut2 = task.get_future();
```

**注意事项**：

1. `get()` 可以多次调用：每次返回同一个结果。这与 `future::get()` 的一次性消费完全不同。
2. 线程安全：多个线程同时对不同副本调用 `get()` 是安全的。多个线程同时访问同一个 `std::shared_future` 对象时，若涉及修改（如赋值），仍需同步；但只调用 `get()` 是安全的。
3. 等待：`wait()`、`wait_for()`、`wait_until()` 的行为与 `std::future` 一致，可以在多个副本上分别调用。
4. 结果类型：`std::shared_future<T>` 的 `get()` 返回 `const T&`（对 `T` 而言），避免每次拷贝。如果 `T` 是引用类型 `T&`，则返回 `T&`。
