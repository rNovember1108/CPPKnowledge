# 类与对象

## 类的默认函数

在 C++ 中，一个类有八个默认函数（若算上取地址运算符则为 8 个，但通常关注前 6 个核心函数）：

1. 默认构造函数；
2. 默认析构函数；
3. 默认拷贝构造函数；
4. 默认重载赋值运算符函数；
5. 默认移动构造函数（C++11）；
6. 默认重载移动赋值操作符函数（C++11）。
7. 默认重载取址运算符函数；
8. 默认重载取址运算符const函数；

## 对象的操作

下面是一个简单的示例代码，演示了如何实现一个基本的字符串类，类似于 C++ 中的 `std::string`，以及在对类对象进行操作时与默认函数之间的调用关系。

```
#include <iostream>

class MyString
{
public:
    // 默认构造函数
    MyString() : data(nullptr), length(0) 
    {
        std::cout << "Default constructor called" << std::endl;
    }

    // 析构函数
    ~MyString() 
    {
        delete[] data;
        std::cout << "Destructor called" << std::endl;
    }

    // 拷贝构造函数
    MyString(const MyString& other) : length(other.length) 
    {
        data = new char[length + 1];
        strcpy_s(data, length + 1, other.data);
        std::cout << "Copy constructor called" << std::endl;
    }

    // 赋值运算符重载
    MyString& operator=(const MyString& other) 
    {
        if (this != &other) {
            delete[] data;

            length = other.length;
            data = new char[length + 1];
            strcpy_s(data, length + 1, other.data);
        }
        std::cout << "Assignment operator overload called" << std::endl;
        return *this;
    }

    // 移动构造函数
    MyString(MyString&& other) noexcept : data(other.data), length(other.length) 
    {
        other.data = nullptr;
        other.length = 0;
        std::cout << "Move constructor called" << std::endl;
    }

    // 移动赋值运算符重载
    MyString& operator=(MyString&& other) noexcept 
    {
        if (this != &other) {
            delete[] data;

            data = other.data;
            length = other.length;

            other.data = nullptr;
            other.length = 0;
        }
        std::cout << "Move assignment operator overload called" << std::endl;
        return *this;
    }

    // 构造函数（字符数组）
    MyString(const char* str) : length(strlen(str)) 
    {
        data = new char[length + 1];
        strcpy_s(data, length + 1, str);
        std::cout << "Constructor called" << std::endl;
    }

    // 获取字符串长度
    int getLength() const {
        return length;
    }

    // 获取字符串内容
    const char* getData() const {
        return data;
    }

private:
    char* data;
    int length;
};

int main()
{
    MyString str1("Hello");              // 构造函数（字符数组）
    MyString str2 = str1;                // 拷贝构造函数
    MyString str3;                       // 默认构造函数
    str3 = str1;                         // 赋值运算符重载

    MyString str4 = "World";             // 构造函数（字符数组）
    MyString str5;                       // 默认构造函数  
    str5 = std::move(str4);              // 移动赋值运算符重载

    MyString str6 = "World2";             // 构造函数（字符数组）
    MyString str7 = std::move(str6);      // 移动构造函数

    std::cout << "str1: " << str1.getData() << std::endl;
    std::cout << "str2: " << str2.getData() << std::endl;
    std::cout << "str3: " << str3.getData() << std::endl;
    //std::cout << "str4: " << str4.getData() << std::endl; //被move赋值后，str4的data指针被置空
    std::cout << "str5: " << str5.getData() << std::endl;
    //std::cout << "str6: " << str6.getData() << std::endl; //被move赋值后，str6的data指针被置空
    std::cout << "str7: " << str7.getData() << std::endl;

    return 0;
}
```

## 五法则 (Rule of Five)

‌**核心概念**‌

如果一个类需要显式定义以下五个特殊成员函数中的‌**任意一个**‌，通常意味着该类直接管理了某种资源（如动态内存、文件句柄、网络连接等），此时往往需要同时定义全部五个函数，以确保资源在拷贝、移动和销毁时行为正确。

这五个特殊成员函数包括：

- **析构函数(Destructor)**
- **拷贝构造函数 (Copy Constructor)**
- **拷贝赋值运算符 (Copy Assignment Operator)**
- **移动构造函数 (Move Constructor)**
- **移动赋值运算符 (Move Assignment Operator)**

**作用**

- ‌**防止资源泄漏与双重释放**‌：编译器默认生成的拷贝操作执行的是“浅拷贝”（即复制指针值）。如果类持有裸指针（如 `int* data`），两个对象将指向同一块内存。当其中一个对象析构时释放了内存，另一个对象再访问或析构时会导致未定义行为（如 Double Free 错误或段错误）。
- ‌**支持移动语义优化**‌：C++11 引入移动语义后，允许将临时对象的资源“窃取”过来，避免昂贵的深拷贝。如果只定义了拷贝操作而未定义移动操作，编译器可能不会生成移动构造函数，导致性能下降；反之，如果定义了移动操作，编译器通常会删除默认的拷贝操作，导致类不可拷贝。

**实现要点**‌

- ‌**深拷贝逻辑**‌：拷贝构造和拷贝赋值必须分配新资源并复制数据。
- ‌**资源转移逻辑**‌：移动构造和移动赋值应将源对象的资源指针转移给当前对象，并将源对象的指针置为 `nullptr`（或有效空状态），防止源对象析构时重复释放。
- ‌**异常安全**‌：移动操作通常应标记为 `noexcept`，以便标准库容器（如 `std::vector`）在扩容时能优先使用移动而非拷贝，提升性能。
- ‌**自赋值检查**‌：在拷贝赋值中需检查自赋值；在移动赋值中，虽然自赋值较少见，但安全的实现通常也能处理自赋值（例如通过 `swap` 或先接管后清空）。

‌**示例场景**‌

  自定义字符串类、智能指针封装、文件流包装器等直接持有裸资源句柄的类。

## 零法则 (Rule of Zero)

**核心概念**‌

**尽量不手动定义任何特殊成员函数**，如果一个类的所有成员变量都使用了遵循 RAII（资源获取即初始化）机制的类型（如 `std::string`, `std::vector`, `std::unique_ptr`,`std::shared_ptr` 等），那么该类不需要编写析构函数、拷贝/移动构造函数或赋值运算符。编译器自动生成的默认版本即可正确处理资源的清理、拷贝和移动。

**作用**

- ‌**安全性更高**‌：手动编写五法则容易出错（如忘记处理异常、遗漏自赋值检查、移动后未置空指针等）。依赖标准库组件可以消除这些人为错误。
- ‌**代码更简洁**‌：减少了大量样板代码，使类专注于业务逻辑而非资源管理细节。
- ‌**性能更优**‌：对于符合“平凡可拷贝”（Trivially Copyable）条件的类，编译器生成的默认拷贝操作可能优化为 `memcpy`，比手写的循环拷贝更快。

‌**实施建议**‌

- ‌**使用智能指针替代裸指针**‌：用 `std::unique_ptr` 或 `std::shared_ptr` 代替 `new/delete`。
- ‌**使用标准容器**‌：用 `std::vector`、`std::string` 代替原生数组和 `char*`。
- ‌**封装资源管理类**‌：如果必须管理非标准资源（如 OpenGL 纹理 ID、数据库连接），应将其封装在一个独立的、遵循五法则的小类中，然后在业务类中使用该封装类的实例，从而使业务类符合零法则。

‌**注意事项**‌

- ‌**成员限制**‌：如果类中包含不可拷贝或不可移动的成员（如 `std::mutex`、`std::atomic`、`std::thread`），编译器生成的默认拷贝/移动操作会被隐式删除。此时需要根据需求显式 `= delete` 拷贝操作，或仅保留移动操作，但这已偏离纯粹的零法则，需小心处理。
- **`= default`的使用**：显式使用 `= default` 并不等同于零法则。虽然它请求编译器生成默认实现，但如果类中存在复杂成员，`= default` 的行为可能与预期不符（例如导致编译失败或退化为低效实现）。零法则强调的是“完全不声明”这些函数，让编译器隐式生成。

## 实战建议

| 特性               | 五法则 (Rule of Five)         | 零法则 (Rule of Zero)        |
| ---------------- | -------------------------- | ------------------------- |
| ‌**适用场景**‌       | 类直接持有裸资源（裸指针、文件描述符、OS 句柄等） | 类仅包含标准库类型、智能指针或其他 RAII 对象 |
| ‌**主要工作**‌       | 手动实现析构、拷贝、移动共5个函数          | 不实现任何特殊成员函数               |
| ‌**复杂度**‌        | 高，需处理异常安全、自赋值、状态重置         | 低，依赖编译器自动生成               |
| ‌**风险**‌         | 易出现内存泄漏、双重释放、野指针           | 极低，除非成员类型本身有误             |
| ‌**现代 C++ 推荐度**‌ | ‌**尽量避免**‌，除非编写底层资源封装库     | ‌**首选**‌，作为日常开发的标准实践      |

在现代 C++ 开发中，应‌**优先遵循零法则**‌。只有在编写极底层的资源封装类（如自定义内存分配器、特定硬件驱动接口）时，才需要考虑五法则。如果发现自己正在为一个业务逻辑类编写析构函数或拷贝控制成员，通常意味着设计存在问题，应尝试引入 RAII 包装器将资源管理剥离出去。 

## C++11新型构造函数方法

### 委托构造

C++11 引入了委托构造的概念，这使得构造函数可以在同一个类中一个构造函数调用另一个构造函数，从而达到简化代码的目的：

```
class Base 
{
public:
    int value1;
    int value2;
    Base() 
    {
        value1 = 1;
    }
    Base(int value) : Base() 
    {  // 委托 Base() 构造函数
        value2 = 2;
    }
};
```

### 继承构造

在继承体系中，如果派生类想要使用基类的构造函数，需要在构造函数中显式声明。 
假若基类拥有为数众多的不同版本的构造函数，这样，在派生类中得写很多对应的“透传”构造函数。如下：

```
class A
{
  A(int i) {}
  A(double d,int i) {}
  A(float f,int i,const char* c) {}
  // ...等等系列的构造函数版本
};

class B : A
{
  B(int i):A(i) {}
  B(double d,int i):A(d,i) {}
  B(folat f,int i,const char* c):A(f,i,e) {}
  // ......等等好多个和基类构造函数对应的构造函数
};
```

C++11 的继承构造：

```
class A
{
  A(int i) {}
  A(double d,int i) {}
  A(float f,int i,const char* c) {}
  // ...等等系列的构造函数版本
};

class B:A
{
  using A::A;
  // 关于基类各构造函数的继承一句话搞定
  // ......
};
```

如果一个继承构造函数不被相关的代码使用，编译器不会为之产生真正的函数代码，这样比透传基类各种构造函数更加节省目标代码空间。
