# 限定与不限定作用域的枚举类型

## 限定作用域与不限定作用域枚举类型语法

1. 限定作用域枚举类型语法

    限定作用域枚举类型‌（Scoped Enumeration），也称为‌强类型枚举‌，是 C++11 引入的特性。它解决了传统枚举（不限定作用域）存在的命名污染和隐式类型转换问题。

    ```
    enum class color
    {
        blue,
        red
    };

    // 或者
    enum struct color
    {
        blue,
        red
    };

    // 两种写法完全一样，推荐使用 enum class，但 enum struct 同样有效
    ```


2. 不限定作用域枚举类型语法

    在 C++ 中，‌不限定作用域的枚举类型，通常被称为“传统枚举”，是 C++98 标准引入的语法。

    ```
    enum color
    {
        blue,
        red
    };
    ```

## 限定作用域枚举类型的优势

1. 作用域内外的同名变量影响

    对于不限定作用域的枚举类型，枚举量直接暴露在包含该枚举定义的外层作用域中，同作用域内不能出现同名标识符。

    ```
    enum color
    {
        blue, red
    };
    auto red = 0; // 错误，red已经在范围内被声明过了
    ```

    限定作用域的枚举类型则不一样，枚举量仅在枚举类型自身的作用域内有效，外层作用域中可以定义与枚举成员同名的变量，不会引发编译错误。

    ```
    enum class color
    {
        blue, red
    }; 
    auto red = false;
    color a = color::red;
    ```

    简单来说，限定作用域枚举的枚举量不会向外扩散，完全被封装在枚举类型的作用域范围内，可以降低对名字空间的污染。

2. 避免隐式类型转换

    ```
    enum color
    {
        blue, red
    };

    color c = red;
    if(c < 5.5)
    {
        ...
    }
    ```

    在上述例子中，`c` 会被隐式转换为了浮点型变量与 `5.5` 进行比较。而在限定作用域的枚举类型中，上述隐式转换的问题则不复存在。

    ```
    enum class color
    {
        blue, red
    };

    color c = color::red;
    if(c < 5.5) // 错误，color型别无法与浮点类型变量进行比较
    {
        ...
    }
    ```

3. 降低因改动产生的编译成本

    不限定作用域枚举类型其底层类型由‌编译器实现定义，编译器会根据枚举成员的值范围，选择一个‌足够容纳所有枚举值的最小整数类型‌（通常是 `int`，但也可能是 `unsigned int`、`short`、`char` 等）。由于编译器会针对不限定作用域枚举类型 `enum` 进行优化，因此，对于以下形式的枚举型别，编译器可能会选择 `char` 作为其底层型别而不是 `int`。

    ```
    enum color{red, blue};
    ```

    然而，若将 `color` 的定义换为以下形式，`char` 变量不足以表示其底层变量，则会改变底层类型，触发重新编译：

    ```
    enum color
    {
        red = 0xfffffff,
        blue = 10000
    }
    ```

    而 C++11 标准明确规定，限定作用域枚举类型如果没有指定底层类型，其底层类型默认为 `int`，不会有改变底层类型并重新编译的风险。

4. 前置声明的使用有所不同

    不限定作用域枚举类型在 C++11 前不可前置声明（因大小未知），C++11 起若指定底层类型则可，而限定作用域枚举类型可直接前置声明（因为大小已知，默认 `int`）。


    ```
    enum type1;     //错误，不限定作用域枚举类型的前置声明应指定成员类型
    enum type2 : unsigned int;      //正确
    enum class type3;          //正确，限定作用域枚举类型成员有默认类型int
    enum class type4 : unsigned int;  //正确，前置声明指定枚举成员类型
    ```

    与所有的声明语句一样，枚举的声明和定义中描述的成员类型必须一致，另外不能在同一个上下文中先声明一个不限定作用域的枚举类型再声明一个同名的限定作用域枚举类型。

    ```
    enum class color : char; //前置声明枚举类
    void Foo(color* p); //前置声明的使用
    //....................
    enum class color : char {RED,GREEN,BLACK,WHITE}; //前置声明的定义
    ```

## 不限定作用域枚举类型的优势

因为枚举成员可以自动转换成整数类型，在需要传入整数的程序中可以直接写枚举成员，可读性高，得益于不限定作用域枚举类型允许隐式类型转换的特性，使用以下方法可以减少开发的负担：

```
// 三个成员分别代表 name，address，score
using userInfo = tuple<string, string, int>;
userInfo a{"小明", "A省B市", 90};
auto val1 = get<1>(a); // 得到了域1的值，即address的值

enum info { name, address, score };
auto val2 = get<address>(a); // 也得到了域1的值
```

与此同时，使用限定作用域的枚举类型，实现上述功能则会复杂很多，需要使用到显示类型转换：

```
enum class info { name, address, score };
auto val = get<static_cast<int>(info::address)>(a);
```

## 总结

在现代 C++ 中，‌优先使用 `enum class`‌，因为它默认类型固定（`int`）、作用域隔离、且不会隐式转换为整数，更加安全。
