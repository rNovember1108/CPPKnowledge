# 经典面试之联合体与大小端判定

在 C++ 中，‌联合（Union）‌ 是一种特殊的用户定义数据类型（或类类型）。它的核心特性是：‌所有成员共享同一块内存空间‌。这意味着在任何给定时刻，联合体只能存储其中一个成员的值。

##  内存模型与大小

联合体的内存布局是其最显著的特征：
- ‌共享内存‌：所有成员从相同的内存地址开始存储。
- ‌大小计算‌：联合体的大小至少等于其‌最大成员‌的大小。
- ‌内存对齐‌：联合体的总大小必须是其最大成员对齐要求的整数倍。

```
union Example1
{
    char c;
    int a;
    double b;
};

union Example2
{
    char arr[10];
    int i;
    double b;
};
```

`sizeof(Example1)` 的值为8，`sizeof(Example2)` 的值为16，计算方式参见《内存对齐》章节，这里不在赘述。

## 特殊规则与限制

与 C 语言不同，C++ 中的联合体更像是一个受限的类（Class）：

1. ‌访问控制‌：联合体可以有 `public`、`protected`、`private` 成员。默认访问权限是 `public`。
2. ‌成员函数‌：可以包含构造函数、析构函数和普通成员函数。
3. 禁止项‌：
    - ‌不能有虚函数‌ (virtual functions)。
    - ‌不能有静态数据成员‌ (static data members)。
    - ‌不能作为基类‌，也不能继承自其他类（在 C++11 之前限制更严，C++11 后允许包含非平凡类型的成员，但有严格构造/析构要求）。
    - ‌不能有引用成员‌ (reference members)，因为引用必须初始化且不能重新绑定，这与联合体覆盖内存的特性冲突。

4. 非平凡类型（Non-trivial types）:
    - 在 C++11 之前，联合体（Union）不能包含具有非平凡构造函数、析构函数或拷贝控制成员的类型（如 std::string、std::vector 或自定义类）。C++11 引入了‌非受限联合体（Unrestricted Unions）‌，允许包含这些非平凡类型，但这也带来了巨大的责任：‌编译器不再自动生成特殊的成员函数，且程序员必须手动管理对象的生命周期‌。要安全地使用包含非平凡类型的联合体，必须遵循“谁活跃，谁负责”的原则，通常结合 ‌Placement New‌（定位 new）来构造对象，并显式调用析构函数。带标签的联合体‌是通过添加一个“类型标识符”来解决原生联合体类型不安全问题的设计模式,在 ‌C++17 及以后‌，应优先使用 ‌std::variant‌，它是该模式的标准化、安全化实现。仅在‌无法使用标准库‌或‌需要极致底层控制‌的特殊场景下，才考虑手动实现带标签的联合体，并需格外小心处理构造、析构和拷贝语义。

    ```
    struct TaggedUnion
    {
        enum class Type
        {
            INT,
            STRING
        }tag;

        union
        {
            int i;
            std::string s;
        };

        // 构造函数：默认初始化为 int
        TaggedUnion() 
            : tag(Type::INT)
            , i(0)
        {}

        // 设置 int
        void setInt(int val)
        {
            if (tag == Type::STRING)
            {
                s.~basic_string(); // 先析构旧的 string , int 自动管理不需要特殊处理
            }

            i = val;
            tag = Type::INT;
        }

        // 设置 string
        void setString(const std::string& val)
        {
            if (tag == Type::STRING)
            {
                s.~basic_string(); // 先析构旧的 string , int 自动管理不需要特殊处理
            }

            new (&s) std::string(val); // 构造新的 string
            tag = Type::STRING;
        }

        // 析构函数：根据 tag 决定如何清理
        ~TaggedUnion()
        {
            if (tag == Type::STRING)
            {
                s.~basic_string();
            }
        }

        // 禁止拷贝/移动，除非你实现了正确的深拷贝逻辑
        TaggedUnion(const TaggedUnion&) = delete;
        TaggedUnion& operator=(const TaggedUnion&) = delete;
    };

    int main()
    {
        TaggedUnion tu;

        tu.setString("World");
        std::cout << tu.s << std::endl;

        tu.setInt(123);
        std::cout << tu.i << std::endl;

        return 0;
    }
    ```

5. ‌匿名联合体 (Anonymous Union)‌：
    - C++ 支持匿名联合体，其成员直接暴露在外层作用域中，无需通过联合体变量名访问。

    ```
    int main()
    {
        union
        {
            int i;
            float f;
        };

        i = 10;

        std::cout << i << std::endl;
        return 0;
    }
    ```

## 大小端

### 定义

1. 小端模式（Little-endian）

    ‌小端模式‌指多字节数据的‌低位字节‌存放在内存的低地址处，‌高位字节‌存放在内存的高地址处。
    以32位整数 `0x12345678` 为例，内存从低地址到高地址的存储顺序为 `78 56 34 12`，x86、多数ARM系统默认采用该模式。

2. 大端模式（Big-endian）

    ‌大端模式‌指多字节数据的‌高位字节‌存放在内存的低地址处，‌低位字节‌存放在内存的高地址处。
    以32位整数 `0x12345678` 为例，内存从低地址到高地址的存储顺序为 `12 34 56 78`，TCP/IP网络协议（网络字节序）、PowerPC架构多采用该模式。

**记忆法**：内存分布跟人类书写读取习惯一致的是大端模式，大端是高位字节存放在低内存地址，小端是高位字节‌存放在的高内存地址。

### 设计意义

1. ‌硬件设计层面‌：它是不同处理器架构的底层设计选择，适配不同硬件运算逻辑，比如x86选小端简化加法器电路，早期大型机选大端贴合人类读写习惯，是硬件效率与设计成本权衡的结果。
2. ‌跨平台兼容层面‌：它是跨系统数据交互的核心基础，TCP/IP协议统一规定用大端作为网络字节序，搭配 `htonl/ntohl` 等转换函数，彻底解决不同端序主机通信时的数据解析错乱问题。
3. ‌底层开发层面‌：它是C/C++等底层语言开发的必备知识点，在嵌入式编程、二进制文件解析、硬件寄存器操作场景中，开发者必须明确端序规则，才能避免数据读取错误，保障程序正常运行。
4. ‌历史生态层面‌：它是计算机软硬件发展的历史遗留结果，两种端序各自积累了大量成熟的硬件、软件生态，强行统一的改造成本极高，保留两种端序共存的状态，是兼顾历史兼容性的最优方案。

### 经典面试应用场景

经常会遇到一道面试题，利用联合体来测试机器是大端模式还是小端模式，代码如下:

```
union EndianChecker
{
    int i;
    char c;
};

int main()
{
    EndianChecker checker;
    checker.i = 1;
    // 如果最低地址处的字节是1，则是小端,否则是大端
    std::cout << (checker.c == 1 ? "小端" : "大端") << std::endl;
    return 0;
}
```

解析：`i` 转换为十六进制值为 `0x00000001`，根据联合体所有成员从相同的内存地址开始存储这一规则，在大端机器上存储为`00 00 00 01`,而在小端机器上存储为`01 00 00 00`,char类型为1字节，读取内存 `+0` 处，内存截断后其值为 `0x00` 和 `0x01` 之一，转为十进制，与 1 进行比较，即可判定机器的大小端模式。
