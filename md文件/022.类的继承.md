# 类的继承

继承是 C++ 面向对象编程的三大基石之一（封装、继承、多态），其在 C++ 中最核心的作用，是建立类型之间的“is-a”（是一种）关系，并以此为基石，实现面向对象编程的三大核心能力：多态、接口规范、代码复用。继承允许我们基于一个已有类（基类）去定义一个新类（派生类），在底层就是内存复制加上成员合并。

## 类的普通继承

我们先来了解最普通的继承，不包含虚函数，不考虑虚继承，最单纯的“is-a”关系。请看下面的代码：

```
class Base
{
public:
    Base()
    {
        std::cout << "Base constructor." << std::endl;
    }

    ~Base()
    {
        std::cout << "Base destructor." << std::endl;
    }

    int a;
    double b;
};

class Derived : public Base
{
public:
    Derived()
    {
        std::cout << "Derived constructor." << std::endl;
    }

    ~Derived()
    {
        std::cout << "Derived destructor." << std::endl;
    }

    int c;
};
```

### 内存布局

实现了一个简单的继承关系，`Derived` 类是 `Base` 类的派生类，`Derived` 类中包含了 `Base` 类的所有成员，包括私有成员。通过测试代码打印出地址信息如下：

```
int main()
{
    Derived derived;

    std::cout << "derived对象地址：" << &derived << std::endl;
    std::cout << "成员a地址：" << &derived.a << std::endl;
    std::cout << "成员b地址：" << &derived.b << std::endl;
    std::cout << "成员c地址：" << &derived.c << std::endl;
    std::cout << "对齐要求大小：" << alignof(Derived) << std::endl;
    std::cout << "内存对齐后大小：" << sizeof(Derived) << std::endl;
    return 0;
}
```

![](..\images\cd859b25b46b4936a4c5b95ede52e19a.png)

可以看到，对象 `derived` 的地址和基类成员 `a` 的地址是一样的，紧接着是基类成员 `b` 的地址，最后是派生类成员 `c` 的地址，这说明基类成员永远在前，派生类成员追加在后面，其内存布局与大小如下：

![](..\images\e9e5b9b7b5a24b2ea5f5f22873cccf5f.png)

关于内存对齐大小计算，可以参见往期文章[内存对齐](015.内存对齐.md)。**注意：如果类中不包含任何成员变量，其大小为 1，而不是 0。这是因为 C++ 标准规定，同一个类的两个不同对象必须拥有不同的内存地址。如果空类大小是 0，那么在定义 `EmptyClass arr[10];` 数组时，所有元素都会挤在同一个地址，导致 `&arr[0] == &arr[1]`，这在语言层面是不允许的。因此，编译器会强制给空类注入一个无用的字节（Dummy Byte），使其大小为 1。**

### 构造与析构顺序

在 C++ 中，对象的构造与析构顺序是确定的，即先构造基类，再构造派生类。相反，析构时，先析构派生类，再析构基类。这确保了派生类构造时，基类的部分已经准备好了。从上述例子中的输出可以看出，创建对象时，`Base` 类的构造函数先调用，这时 `Base` 类的成员 `a` 和 `b` 相继被初始化。然后是 `Derived` 类的构造函数，这时 `Derived` 类的成员 `c` 被初始化。释放时，先是 `Derived` 类的析构函数被调用，这时 `Derived` 类的成员 `c` 生命周期结束，然后是 `Base` 类的析构函数，这时 `Base` 类的成员 `b` 和 `a` 生命周期结束。

在继承的写法中，如果基类没有默认构造函数，那么派生类的构造函数必须显式调用基类的构造函数。否则，编译器会报错。我们将 `Base` 类的构造函数改为有参构造函数，使编译器不再生成默认构造函数，修改如下：

```
Base(int initA, double initB)
    : a(initA), b(initB)
{
    std::cout << "Base constructor." << std::endl;
}
```

派生类 `Derived` 的构造函数必须显式调用基类的构造函数：

```
Derived(int initA, double initB)
    : Base(initA, initB)
{
    std::cout << "Derived constructor." << std::endl;
}
```

### 继承访问控制权限

上面例子中，我们在声明 `Derived` 类时，使用的是 `class Derived : public Base`，注意句中的 `public` 关键字，类似可用的关键字还有 `protected` 和 `private`。三种都可以用于声明派生类，但它们对应不同的访问控制权限。如果省略关键字，默认继承是 `private`，这一点要注意。

![](..\images\5eddef200c4e46a8a541165ea024f0d6.png)

使用技巧：
1. 绝大多数的情况只用 `public` 继承。
2. `protected` 继承几乎不用（因为语义模糊，既不是真正的 “is-a” 关系，也不如组合清晰）。
3. `private` 继承可以用，但通常用组合（`has-a`）替代。


## 类的虚继承

### 菱形继承的问题

上面我们介绍了在普通继承的过程中，派生类会完整地包含基类的所有成员。那么考虑下面的情况：

```
class A
{
public:
    A() : a(1) {}

    int a;
};

// 普通继承
class B : public A
{
public:
    int b;
};

// 普通继承
class C : public A
{
public:
    int c;
};

// 普通多继承
class D : public B, public C
{
public:
    int d;
};
```

当出现菱形继承时（即 `B` 和 `C` 都继承自 `A`，`D` 同时继承 `B` 和 `C`），`D` 的对象中会包含两份 `A` 的副本。其内存布局大致如下：

![](..\images\a741c0055ef5484b8825ab7e36c89720.png)

以下测试代码将会报错，因为对 `a` 的访问不明确：

```
int main()
{
    D test;
    std::cout << test.a << std::endl;
    return 0;
}
```

这个时候，我们必须通过**作用域限定符**来指明要访问的是哪个基类的成员，即 `test.B::a` 或 `test.C::a`。

```
int main()
{
    D test;
    std::cout << test.B::a << std::endl;
    return 0;
}
```

这种情况下，我们可以使用 `virtual` 关键字，告诉编译器“这个基类在整个继承体系中共享同一个实例”，这样消除了数据冗余和二义性，无论中间有多少条继承路径，最终派生类中只有一份最顶层的虚基类子对象。这就是**虚继承**。

```
class A
{
public:
    A() : a(1) {}

    int a;
};

// 虚继承
class B : virtual public A
{
public:
    int b;
};

// 虚继承
class C : virtual public A
{
public:
    int c;
};

// 虚继承后，D 只含一份 A
class D : public B, public C
{
public:
    int d;
};
```

`B` 和 `C` 都是采用虚继承的方式继承自 `A`，所以 `D` 只含一份 `A` 的副本。每次通过 `D` 类对象访问 `a` 时，编译器通过 vbptr（虚基类指针）间接计算偏移量，定位到唯一的 `A` 对象。
其内存布局大致如下：

![](..\images\07f1e805d7ad49bfb8e0bf9ef406b09b.png)

为什么叫“虚继承”呢？ `A` 的成员不再分属两个分支，而是放在对象内存的最末尾，全局只有一份，需要通过 vbptr 间接访问（虚的）。

### 虚基类构造函数的特殊规则

虚基类的构造函数由最终派生类调用，而不是由它的直接子类调用。

```
class A
{
public:
    A(const std::string& name) : name(name)
    {
        std::cout << "A constructor: " << name << std::endl;
    }
    std::string name;
};

class B : virtual public A
{
public:
    B() : A("from B")
    {
        std::cout << "B constructor" << std::endl;
    }
};

class C : virtual public A
{
public:
    C() : A("from C")
    {
        std::cout << "C constructor" << std::endl;
    }
};

class D : public B, public C
{
public:
    D() : A("from D"), B(), C()
    {
        std::cout << "D constructor" << std::endl;
    }
};

int main()
{
    D test;
    return 0;
}
```

从最终运行结果可以看出，是 `D` 类触发了 `A` 的构造函数，而不是 `B` 和 `C`。因为 `A` 只有一份，如果让 `B` 和 `C` 各自初始化它，谁来最终决定参数值？为避免冲突，C++ 规定：只有最终派生类 `D` 才有资格初始化 `A`，中间类的初始化调用会被悄悄忽略。

虽然使用虚继承可以避免数据冗余和二义性，但是它也会引入一些额外的复杂性。例如：
1. 性能下降：每次访问虚基类的成员，都要通过 vbptr 做间接寻址（比直接偏移慢）。
2. 内存增加：每个虚继承的子类对象里会多一个 vbptr 指针。
3. 构造复杂度剧增：虚基类的构造函数由最终派生类调用，而不是由它的直接子类调用。
4. 代码可读性变差：看代码时，很难一眼看出继承关系。

### 虚继承和普通继承的使用场景

1. 有菱形继承（同一个基类被多次间接继承），必须用虚继承，否则会出现数据冗余和访问二义性。
2. 单继承链（A → B → C），不用虚继承，虚继承会带来额外开销，毫无必要。
3. 组合关系（`has-a`），永远不要用继承，应使用成员变量组合实现。

## 类的多态继承

C++ 的多态分为**静态多态（编译时多态）**和**动态多态（运行时多态）**。其中动态多态就是通过类的多态继承来实现同一行为（接口），在不同对象上表现出不同的形态（实现），即允许通过基类指针或引用调用不同派生类的重写函数，实现“一个接口，多种实现”。

### 多态继承实现要素

要实现多态继承，有以下四点核心要素：
1. 继承：派生类继承基类
2. 虚函数：基类中使用 `virtual` 关键字声明函数
3. 重写：派生类重新定义虚函数
4. 向上转型：基类指针/引用指向派生类对象

```
class Base
{
public:
    Base()
    {
        std::cout << "Base constructor" << std::endl;
    }

    // 虚析构函数 - 确保正确释放派生类资源
    virtual ~Base()
    {
        std::cout << "Base destructor" << std::endl;
    }

    // 虚函数 - 支持多态
    virtual void Print()
    {
        std::cout << "Base::Print" << std::endl;
    }
};

// 派生类1
class Derived1 : public Base
{
public:

    Derived1()
    {
        std::cout << "Derived1 constructor" << std::endl;
    }

    ~Derived1()
    {
        std::cout << "Derived1 destructor" << std::endl;
    }

    // 重写虚函数 (override 是C++11关键字，可选但推荐)
    virtual void Print() override
    {
        std::cout << "Derived1::Print" << std::endl;
    }
};

// 派生类2
class Derived2 : public Base
{
public:
    Derived2()
    {
        std::cout << "Derived2 constructor" << std::endl;
    }

    ~Derived2()
    {
        std::cout << "Derived2 destructor" << std::endl;
    }

    // 重写虚函数 (override 是C++11关键字，可选但推荐)
    virtual void Print() override
    {
        std::cout << "Derived2::Print" << std::endl;
    }
};

int main()
{
    Base* ptr1 = new Derived1();
    ptr1->Print();
    delete ptr1;
    ptr1 = nullptr;

    std::cout << "===========分割线=============" << std::endl;
    Base* ptr2 = new Derived2();
    ptr2->Print();
    delete ptr2;
    ptr2 = nullptr;

    return 0;
}
```

运行以上代码，输出结果如下：

![](..\images\77cd91c996d649ca95b2e8e609a48ed9.png)

按照常理认知，我们使用 `Base` 的指针来调用 `Print()` 函数，理应打印出 `Base::Print`，但是实际情况却是，打印出 `Derived1::Print` 和 `Derived2::Print`，代码中几处 `virtual` 的使用正是关键因素。`Derived1` 和 `Derived2` 都是 `Base` 类的派生类，它们都重新定义了 `virtual void Print()` 函数，拥有自己的实现，这是一个虚函数的重写。当通过指向派生类对象的 `Base` 指针调用 `Print()` 函数时，会调用派生类的 `Print()` 函数，而不是基类的 `Print()` 函数，从而打印出不同的结果。当然，代码中使用了继承的机制，基类和派生类的构造函数与析构函数的调用顺序跟我们前一篇文章中的描述是一样的。

### 多态继承实现原理

为什么我们只是添加了一些 `virtual` 关键字，就可以实现多态继承了？这就不得不介绍几个相关概念：**虚函数**、**虚指针**、**虚函数表**。

#### 虚函数

虚函数是指用 `virtual` 关键字修饰的成员函数，其作用是告诉编译器这个函数需要动态绑定。上述代码中 `Base` 类的 `Print()` 函数就是虚函数，它使用了 `virtual` 关键字修饰。

- **重写（覆盖）**：发生在派生类与基类之间，函数签名完全相同，且基类函数必须是 `virtual`。

    这样的情况既是动态绑定，构成多态。当然在派生类中你也可以不使用 `virtual` 修饰，但这并不影响其虚函数的属性，因为虚函数的虚属性是沿继承链向下传递的。C++ 标准规定如果某个函数在基类中被声明为 `virtual`，那么在派生类中重写该函数的函数也是 `virtual`，无论是否显式使用 `virtual` 关键字。`virtual` 关键字在派生类中仅仅是提示性修饰符（为了代码可读性），而不是必要条件。我们通常会在派生类函数最后添加 `override` 关键字，以示其是一个重写的虚函数，有助于防止拼写错误、参数类型不匹配、返回值类型不兼容、基类函数不是虚函数等各种意外的发生。`override` 告诉编译器，这个函数必须重写基类中的某个虚函数，如果不是，就报错。示例如下：

    ```
    class Base
    {
    public:
        virtual void Print()
        {
            std::cout << "Base::Print" << std::endl;
        }

        // 虚析构函数
        virtual ~Base() {}
    };
    
    // 派生类
    class Derived : public Base
    {
    public:

        // 重写虚函数 (override 是C++11关键字，可选但推荐)
        virtual void Print() override
        {
            std::cout << "Derived::Print" << std::endl;
        }
    };
    ```

- **隐藏**：发生在派生类与基类之间，只要函数名相同，但不满足重写条件（基类非 `virtual`，或参数不同，或返回类型不兼容）。

    这样的情况即是静态绑定，不构成多态。但派生类的函数会隐藏基类的函数，而不是重写基类的函数。即使你用同样的方法，使用基类指针指向派生类对象来调用`Print()` 函数，最终也只会调用基类的函数。而如果你使用派生类指针指向派生类对象来调用`Print()` 函数，最终会调用派生类的函数。上一篇文章我们提到派生类是包含了基类所有成员的，那么我们该怎么让它调用基类的`Print()` 函数呢？记得菱形继承中的作用域限定符吗？使用作用域限定符，就能够调用到。示例如下：

    ```
    class Base
    {
    public:
        void Print()
        {
            std::cout << "Base::Print" << std::endl;
        }
    };
    
    // 派生类
    class Derived : public Base
    {
    public:

        // 隐藏基类同名函数
        void Print()
        {
            std::cout << "Derived::Print" << std::endl;
        }
    };
    ```

#### 虚指针

虚指针（vptr）是指每个对象内部隐含的一个指针（32位系统下占用 4 字节），指向该对象所属类的虚函数表。其值通常在对象构造时由编译器注入的代码赋值。在对象的内存布局中，虚指针通常位于对象的最开头。

我们用一段测试代码来证明一下虚指针的存在：

```
class A
{
public:
    int x;
    virtual void b() {}
};

int main()
{
    A* p = new A;
    std::cout << p << endl;
    std::cout << &p->x << endl;
    
    return 0;
}
```

定义了一个类 `A`，含有一个成员变量 `x` 和一个虚函数 `b()`，首先我们计算类在 32 位系统下的大小，可以发现如果 `b()` 是一个虚函数，类 `A` 的大小为 8，如果不是，类 `A` 的大小为 4，相差 4 字节，正好是一个指针大小。然后我们创建了一个指针 `p` 指向 `A` 的对象，输出对象的地址和对象成员 `x` 的地址，我们想一下，如果对象的地址和 `x` 的地址相同，那么就意味着编译器把虚指针放在了末尾，如果两个地址不同，那么就意味着虚指针是放在最前面的。运行结果为十六进制，我们把它转为十进制观察一下：

![](..\images\6b2d8a3392a8332ae5014089cf30c6d0.png)

可以观察到结果是不同的，而且正好相差了 4 个字节，由此可见，**对象在构造时，编译器会隐式注入一个虚指针，通常位于对象首地址处**。


#### 虚函数表

虚函数表（vtable）是指编译器为每个包含虚函数的类生成的函数指针数组，存储该类所有虚函数的实际地址。其是在编译阶段就生成的，通常放在只读数据段（.rodata）中。表中按声明顺序存储所有虚函数的入口地址，如果派生类重写了某个虚函数，表中对应条目替换为派生类版本。

既然虚函数表是真实存在的，并且是由对象的虚指针所指向，那么我们是否可以通过虚指针来获取到虚函数表的内容呢？我们来看以下示例：

```
class Base
{
public:
    virtual void a() { std::cout << "Base a()" << std::endl; }
    virtual void b() { std::cout << "Base b()" << std::endl; }
    virtual void c() { std::cout << "Base c()" << std::endl; }
};

class Derived : public Base
{
public:
    virtual void b() { std::cout << "Derived b()" << std::endl; }
};
```

定义了基类 `Base` 与派生类 `Derived`，其中派生类重写了基类的虚函数 `b()`。我们来想想办法看能不能将它们的虚函数表打印出来。已知虚指针是放在对象内存布局的最前面，那么对象的地址既是虚指针的地址，我们再对虚指针进行解引用，就可以得到虚函数表的首地址（虚函数表是一个函数指针数组），再遍历数组打印，即可得到虚函数表的内容。

```
int main()
{
    std::cout << "-----------Base------------" << std::endl;
    Base* p1 = new Base;
    uintptr_t* vptr1 = (uintptr_t*)p1; // 对象地址既是虚指针地址
    uintptr_t* vtable1 = (uintptr_t*)(*vptr1); // 解引用虚指针，得到虚函数表的首地址
    for (int i = 0; i < 3; i++) // 遍历虚函数表，打印每个虚函数的地址
    {
        printf("vtable[%d] : %p\n", i, (void*)vtable1[i]);
    }

    Derived* p2 = new Derived;
    uintptr_t* vptr2 = (uintptr_t*)p2;
    uintptr_t* vtable2 = (uintptr_t*)(*vptr2);
    std::cout << "---------Derived------------" << std::endl;
    for (int i = 0; i < 3; i++)
    {
        printf("vtable[%d] : %p\n", i, (void*)vtable2[i]);
    }

    return 0;
}
```

观察结果，我们可以发现 `Base` 类和 `Derived` 类的虚函数表中确实分别拥有三个地址，但我们也不能确定这三个地址就是 `a()`、`b()`、`c()` 的函数地址。如果要确认这一点，我们需要将这三个地址转换为函数指针，并调用它们，看是否能正常调用并打印出相应的函数输出。改动如下：

```
int main()
{
    typedef void (*Func)(); // 定义函数指针类型

    std::cout << "-----------Base------------" << std::endl;
    Base* p1 = new Base;
    uintptr_t* vptr1 = (uintptr_t*)p1; // 对象地址既是虚指针地址
    uintptr_t* vtable1 = (uintptr_t*)(*vptr1); // 解引用虚指针，得到虚函数表的首地址
    for (int i = 0; i < 3; i++) // 遍历虚函数表，打印每个虚函数的地址
    {
        printf("vtable[%d] : %p\n", i, (void*)vtable1[i]);

        // 转换为函数指针并调用
        Func func = (Func)vtable1[i];
        func();
    }

    Derived* p2 = new Derived;
    uintptr_t* vptr2 = (uintptr_t*)p2;
    uintptr_t* vtable2 = (uintptr_t*)(*vptr2);
    std::cout << "---------Derived------------" << std::endl;
    for (int i = 0; i < 3; i++)
    {
        printf("vtable[%d] : %p\n", i, (void*)vtable2[i]);

        // 转换为函数指针并调用
        Func func = (Func)vtable2[i];
        func();
    }

    return 0;
}
```

#### 虚函数中的默认参数

在 C++ 中，虚函数的调用是动态绑定的（运行时决定），但默认参数却是静态绑定的（编译时决定）。这两者的绑定时机不同，就导致了一个奇怪的现象。请看如下代码：

```
class Base
{
public:
    virtual void func(int x = 10)
    {
        cout << "Base: " << x << endl;
    }
};

class Derived : public Base
{
public:
    void func(int x = 20) override
    {
        cout << "Derived: " << x << endl;
    }
};

int main()
{
    Base* ptr = new Derived();
    ptr ->func();
    delete ptr;
    return 0;
}
```

你是不是以为程序会输出 `Derived: 20`， 但根据结果来看，程序却输出了 `Derived: 10`。这是因为编译器在编译时看到 `ptr->func()` 时，`ptr` 的类型是 `Base*`，查找 `Base::func()` 的声明，发现默认参数是 10，所以将调用展开为: `ptr->func(10)`。在运行时，通过 `vptr` 找到 `Derived` 的虚函数表，调用 `Derived::func(int x)`，此时 `x = 10`，已经在编译时确定。

#### 注意事项

1. 基类必须有虚析构函数，确保派生类正确释放。
2. 虚函数调用有轻微性能损失（间接寻址）。
3. 构造函数、静态函数、友元函数不能是虚函数。
4. 默认参数在虚函数中要谨慎（静态绑定），实际工程中应保持默认参数值一致或不在重写函数中重新指定。

## 类的多重继承

C++ 的多重继承是指一个派生类可以同时从多个基类继承。

### 普通类的多重继承

我们通过一个简单的例子来说明普通类的多重继承相关的内容：

```
class Base1
{
public:
    Base1() { std::cout << "Base1 constructor" << std::endl; }
    ~Base1() { std::cout << "Base1 destructor" << std::endl; }
    void func1() { std::cout << "Base1::func1" << std::endl; }
private:
    int a;
};

class Base2
{
public:
    Base2() { std::cout << "Base2 constructor" << std::endl; }
    ~Base2() { std::cout << "Base2 destructor" << std::endl; }
    void func2() { std::cout << "Base2::func2" << std::endl; }
private:
    int b;
};

// 派生类同时继承自Base1和Base2
class Derived : public Base1, public Base2
{
public:
    Derived() { std::cout << "Derived constructor" << std::endl; }
    ~Derived() { std::cout << "Derived destructor" << std::endl; }
    void func3() { std::cout << "Derived::func3" << std::endl; }
private:
    int c;
};

int main()
{
    Derived* d = new Derived;
    d->func1();  // 从Base1继承
    d->func2();  // 从Base2继承
    d->func3();  // 自己的函数

    delete d;
    d = nullptr;
    return 0;
}
```

运行结果如下图所示：

![](..\images\a1343c0b8d5d1134c8dcc83c68f02560.png)

从结果分析可以看出以下几点：

1. 构造/析构顺序：先构造基类，再构造派生类。其中多个基类的构造顺序按照派生类声明时继承出现的顺序构造。析构则是刚好与构造完全相反的顺序。上面例子中，`Derived` 类继承时是先 `Base1` 再 `Base2`，所以我们可以看到输出的顺序是：

    ```
    Base1 constructor
    Base2 constructor
    Derived constructor
    Derived destructor
    Base2 destructor
    Base1 destructor
    ```

    如果我们将继承时的顺序调换，那么构造顺序也会改变：

    ```
    class Derived : public Base1, public Base2
    改为
    class Derived : public Base2, public Base1

    // 注意是派生类声明时的顺序，而不是其他
    // 派生类构造函数的初始化列表不能影响顺序
    // 如：Derived() : Base2(), Base1()
    ```

    使用上面改动后代码，将输出：

    ```
    Base2 constructor
    Base1 constructor
    Derived constructor
    Derived destructor
    Base1 destructor
    Base2 destructor
    ```

2. 内存布局顺序：`Derived` 同时继承自 `Base1`和 `Base2`，然后自己还有一个函数 `func3()`。`Derived` 的对象指针 `d` 可以调用 `Base1` 和 `Base2` 中的函数，也可以调用 `Derived` 中的函数。甚至在内存布局中同时拥有 `a`、`b`、`c` 三个成员变量。这与前面章节中讲到的内容一模一样，区别就在于多重继承中，派生类同时包含多个基类的成员，内存布局也会按照派生类声明时继承出现的顺序布局。其内存布局如下：

    ![](..\images\9f4e2f7d5c6145448530146c167c4caf.png)

3. 调用同名基类成员：当多个基类有同名成员时，使用派生类调用时，必须通过**作用域限定符**来指明要访问的是哪个基类的成员。如：`Base1::func()` 或者 `Base2::func()`。

### 含虚函数类的多重继承

同样我们通过一个例子来说明含虚函数类的多重继承相关的内容：

```
class Base1
{
public:
    Base1() { std::cout << "Base1 constructor" << std::endl; }
    virtual ~Base1() { std::cout << "Base1 destructor" << std::endl; };
    virtual void func1() { std::cout << "Base1::func1" << std::endl; }
    virtual void func2() { std::cout << "Base1::func2" << std::endl; }
    int a;
};

class Base2
{
public:
    Base2() { std::cout << "Base2 constructor" << std::endl; }
    virtual ~Base2() { std::cout << "Base2 destructor" << std::endl; };
    virtual void func3() { std::cout << "Base2::func3" << std::endl; }
    virtual void func4() { std::cout << "Base2::func4" << std::endl; }
    int b;
};

class Derived : public Base1, public Base2
{
public:
    Derived() { std::cout << "Derived constructor" << std::endl; }
    virtual ~Derived() { std::cout << "Derived destructor" << std::endl; };

    // 覆盖Base1的虚函数
    void func1() override { std::cout << "Derived::func1" << std::endl; }

    // 覆盖Base2的虚函数
    void func3() override { std::cout << "Derived::func3" << std::endl; }

    // 新增虚函数
    virtual void func5() { std::cout << "Derived::func5" << std::endl; }

    int c;
};

int main()
{
    std::cout << sizeof(Derived) << std::endl;
    Derived* d = new Derived;
    d->func1();
    d->func3();
    d->func5();

    delete d;
    d = nullptr;
    return 0;
}
```

运行结果如下图所示：

![](..\images\aa2cbbb5b120406ca830b086fc938860.png)

从结果分析同样可以看出以下几点：

1. 构造/析构顺序：这一点与普通类的多重继承一致，不再过多赘述。
2. 内存布局顺序：在32位系统下，派生类 `Derived` 的内存大小为 20 字节，除了包含的成员变量 `a`、`b`、`c`，共计 12 字节外，还剩下了 8 字节的内容，分为了两个 4 字节的虚指针，分别指向对应从 `Base1` 和 `Base2` 拷贝并修改而来的虚函数表。`Derived` 对象的内存布局如下：

    ![](..\images\2c33a736b2f3b0c93425bf3255f3eb0e.png)

观察`Derived` 对象的内存布局，我们会发现几个有意思的问题，以下我们一一分析：

1. 为什么两个虚函数表中出现了两个虚析构函数的地址？

    因为无论通过哪个基类指针去 `delete` 派生类对象，都要求必须能够正确调用到派生类的析构函数，并且释放整个对象的内存。两个虚表都包含析构函数地址，是为了让任意基类指针都能安全地销毁对象。

    `Derived` 对象内部有两个虚指针，`vptr1`（指向 `Base1` 对应的虚函数表）和 `vptr2`（指向 `Base2` 对应的虚函数表）。当你用 `Base1* p1 = &d;` 时，`p1` 指向 `Base1` 子对象（以 `vptr1` 开头）。当你用 `Base2* p2 = &d;` 时，`p2` 指向 `Base2` 子对象（以 `vptr2` 开头）。如果 `Base2` 对应的虚函数表中没有析构函数，那么 `delete p2;` 将无法找到析构入口，程序崩溃。

    两个表中的虚析构函数地址不同（主虚函数表（vtable #1）存放真实析构函数入口地址，次虚函数表（vtable #2）存放 thunk 地址），如果没有实现虚析构函数，那么虚函数表中不会有对应的虚析构函数地址。

2. 为什么 `Derived` 独有的虚函数 `func5()` 的地址是放在**主虚函数表**（即 `vtable #1`）中的？

    **备注：在多重继承中，派生类会有多个虚函数表（对应多个基类）。编译器会选定第一个继承的基类作为主基类。主虚函数表由主基类的虚函数表内容 + 派生类新增虚函数组成。次虚函数表只包含对应基类的虚函数（重写的部分会被替换），末尾不追加派生类新增虚函数。**

    这并不是 C++ 标准的强制规定，本质是为了**单 `vptr` 寻址 + 零 `this` 调整开销**的最优实现，是编译器在权衡**运行效率**与**内存布局**后做出的工程决策。这样存放的主要原因有以下几点：

    1. 为了保持单继承下的内存布局简单高效：在单继承（只有一个基类）的情况下，整个对象只有一个虚函数表，那新增的虚函数只能放在这张表里。这保证了对象模型的一致性。无论调用基类虚函数还是派生类新增虚函数，都通过同一个 `vptr` 偏移寻址，不需要额外的指针跳转，执行效率最高。
    2. 为了兼容基类指针的调用逻辑：当使用基类指针指向派生类对象时，编译器只知道基类的虚函数表布局。如果派生类新增的虚函数不放在基类虚函数表的可见区域，基类指针就无法安全地通过偏移量来确定函数位置。而放在主虚函数表的末尾，既不影响基类原有虚函数的索引位置（保证了多态的正确性），又让派生类指针在调用新虚函数时能通过相同的 `vptr` + 偏移量快速找到。
    3. 多重继承下的主虚函数表特殊地位：在多重继承中，派生类会有多个虚表（对应多个基类）。编译器会选定第一个继承的基类作为主基类，其虚函数表作为主虚函数表。
    4. 汇编层面的底层逻辑：假设派生类新增了虚函数 `Derived::func5()`，如果把它放在非主虚函数表中，调用时，编译器必须先判断当前是哪个基类指针，然后额外进行一次 `this` 指针调整（`this += offset`），再去查找对应的次虚函数表。这会增加指令开销。而放在主虚函数表中，所有新增虚函数和主基类虚函数共享同一个 `vptr`，此时 `this` 指针无需调整，直接通过固定偏移量 `call [vptr + offset]` 即可。

3. 为什么 `vtable #2` 中出现了一个名为 `thunk` 的新词语，而 `vtable #1` 中没有出现？

    **备注：`thunk` 是一小段由编译器自动生成的、不可见的汇编代码（机器码）。它不直接执行你的业务逻辑，而是在执行真正的虚函数之前，先调整 `this` 指针，然后跳转过去。你可以把它想象成是一个“指针修正器 + 跳板”，在含虚函数的类多重继承下，是必须的。**

    为什么需要 `thunk` 呢？假设有以下代码：

    ```
    class Base1
    {
    public:
        virtual void f1()
        {
            std::cout << "Base1::f1" << std::endl;
        }
    };
    class Base2
    {
    public:
        virtual void f2()
        { 
            std::cout << "Base2::f2" << std::endl;
        }
    };

    class Derived : public Base1, public Base2
    {
    public:
        virtual void f2() override
        {
            // 重写 Base2 的 f2 函数
            std::cout << "Derived::f2" << std::endl;
        }
    };
    ```

    `Derived` 对象的内存布局如下：

    ![](..\images\a8428a32e3a7f44d21583ee14c3d2923.png)

    当你用 `Base2` 的指针调用 `f2()` 时：

    ```
    Derived d;

    // p 指向的是 Derived 对象内部的
    // Base2 子对象起始地址（偏移 4 字节，32位系统）
    Base2* p = &d;

    // 调用 Derived::f2()
    p->f2();
    ```

    此时，`p` 指针的值是 `&d + 4`。但是 `Derived::f2()` 是 `Derived` 类的成员函数，它要求传入的 `this` 指针必须是 `Derived` 对象的起始地址（即 `&d`），而不是 `&d + 4`。如果不做修正，`Derived::f2()` 内部的成员变量访问就会错位，可能导致崩溃。

    那么 `thunk` 是如何解决这个问题的呢？
    
    编译器的做法是：在次虚函数表（即 `Base2` 对应的那张表）中，不直接放 `Derived::f2()` 的地址，而是放一个 `thunk` 的地址。

    其调用流程如下：
    1. `p->f2()`：从 `Base2` 对应的虚函数表中取出槽位。
    2. 发现槽位里存的是 `thunk` 的地址。
    3. CPU 执行 `thunk` 代码：`this -= 4`。
    4. 跳转到真正的 `Derived::f2()` 函数体。
    5. 此时 `this` 正确指向 `&d`，函数顺利执行。

4. 虚函数表中偏移槽位是个什么东西？

    **备注：虚函数表是一个函数指针数组，每个虚函数占据一个固定索引（槽位，`slot`）。“偏移槽位”就是通过一个固定的字节偏移或索引偏移，在 `vtable` 中定位某个虚函数入口。**

    上一篇文章我们提到，`vtable` 中的每个槽位都是一个函数指针，指向对应的虚函数，我们也通过代码遍历槽位并且打印出每个槽位的地址。但你有没有发现，我们遍历的时候起始 `index` 是从 0 开始的。其实，`vtable` 的槽位还有负数槽位，比如 `-1`、`-2` 等。那么它们里面存放的又是什么呢？

    GCC 和 Clang 编译器遵循 Itanium C++ ABI，其虚表在第一个虚函数指针之前固定存放两个条目：
    1. 槽位 -1：RTTI 指针（`type_info`），存储指向 `std::type_info` 对象的指针，用于支持 `typeid` 操作符和 `dynamic_cast` 类型转换。只要类有虚函数（即存在 `vtable`），编译器就会在 -1 槽填入 RTTI 信息。派生类和基类的 RTTI 指针指向不同的 `type_info` 对象，以区分类型。
    2. 槽位 -2：`offset_to_top`（到顶部的偏移），存储当前子对象相对于完整对象起始地址的偏移量（以字节为单位）。在多重继承下，用于 `dynamic_cast` 正确调整 `this` 指针。在虚继承下，用于定位虚基类子对象的位置。对于单继承或位于对象顶部的基类，`offset_to_top = 0`。对于多重继承中非第一个基类的虚表，`offset_to_top` 为负值（因为该子对象在对象内部存在偏移）。

    MSVC 编译器的虚表（`vtable`）在第一个虚函数指针之前，只固定放置一个条目（Clang 在 Windows 上也默认使用 MSVC ABI）:
    1. 槽位 -1：存放一个指向 RTTI Complete Object Locator (COL) 结构的指针。这个结构本身包含了用于运行时类型识别（RTTI）和定位完整对象所需的信息。
    2. 槽位 -2：MSVC 的 `vtable` 在 -1 位置之前不再有 ABI 定义的条目。-2 位置的内容取决于相邻内存，不属于 `vtable` 结构。

### 总结

- 每一个包含虚函数的类都会有自己的虚指针和虚函数表，派生类的虚指针和虚函数表的数量根据继承的含有虚函数的基类的数量来定。
- 派生类对象中虚指针的内存布局顺序，和声明继承时基类的顺序相同。
- 派生类自己的虚函数放在第一个虚函数表（即主虚表）的后面，顺序也是和定义时顺序相同。
- 对于派生类如果要重写父类中的虚函数，那么会在其虚函数表中代替其位置。
- override 可以避免因签名不匹配导致意外隐藏父类的虚函数。
- 如果某个基类不想被继承，用 `final` 关键字，其还可修饰虚函数，阻止派生类继续重写该函数。
- 多重继承主要用于实现多个纯虚接口。
- 基类析构函数尽量用 `virtual` 关键字声明为虚函数。
