# std中move与forward

C++11 引入了右值引用的概念，使得我们能够把引用与右值进行绑定。虽然它看起来像两个“取地址符号”（`&`）连在一起，但在 C++11 的语境下，`&&` 具有全新的含义：‌**右值引用声明符‌**。如下：

```
int&& rvalue_ref = 10;
```

## 左值和右值

### 如何区分左值与右值

1. 通过赋值运算符 `=` 划分

- 左值：可以放到赋值运算符左侧的东西叫左值，代表一个持久的、有身份的对象，可以被修改（除非是 `const`）。
- 右值：只能放到赋值运算符右侧的东西就叫右值，通常是一个临时值、计算结果或字面量，没有持久的身份，不能被直接赋值。

2. 通过是否可取地址划分

- 左值：有名字（通常是一个变量名、函数名或引用），‌可取地址（使用 `&` 运算符获取其内存地址），生命周期持久（在表达式结束后依然存在）的东西就是左值。
- 右值：无名字（通常是匿名临时对象），不可取地址（对右值使用 `&` 运算符会导致编译错误，除非使用特殊技巧，但常规意义上不可取址），生命周期短暂‌（通常在当前表达式结束后立即销毁）的东西就是右值。


```
int b = 1, c = 2;
int a = b + c;
```

①、`a`、`b`、`c` 是左值，有变量名，可以取地址，生命周期持久（直到作用域结束），也可以放到等号左边。

②‌、表达式 `b+c` 的结果是右值，没有名字，不能取地址，生命周期短暂‌（赋值给 `a` 后立即销毁），`&(b+c)` 不能通过编译，而且也不能放到等号左边。

③、数字 `1`、`2` 作为普通字面量是右值。

### 常见的左值与右值

左右值的区别很明显，左值有持久的状态，而右值要么是字面常量，要么是在表达式求值过程中创建的临时对象。

1. 左值：
- 变量名（代表内存中的一块特定区域，只要变量作用域未结束，它就存在）
- 函数名（本身也是一个左值，它可以转换为函数指针）
- 返回左值引用的函数调用（如果函数返回类型是左值引用 `T&`，那么该函数调用的结果是一个左值）
- 前置自增/自减表达式（如：`++i`、`--j`，前置运算符先修改变量，然后返回‌变量本身‌的引用。因为返回的是引用，所以结果是左值）
- 由赋值表达式或赋值运算符连接的表达式（如：`a=b`, `a+= b` 等，这意味着赋值表达式的结果是一个左值，可以继续进行链式赋值或作为其他左值引用的绑定目标）
- 解引用表达式（如：`*p`，对指针进行解引用操作，得到的是指针所指向的对象。既然指向的是一个实际存在的对象，那么结果自然是一个左值）
- 字符串字面值（如：`abcd`，跟其他字面量有点不太一样，字符串字面值存储在静态存储区，具有静态生命周期，因此它们是‌左值‌，但它们却是 `‌const` 左值‌，不能修改内容）

2. 右值：
- 返回值的函数调用‌（如果函数返回非引用类型 `T`，结果是右值）
- 算术表达式‌（如：`a+b`, `x*2`，这些计算产生临时结果）
- 后置自增/自减表达式（如：`i++`, `j--`，返回的是临时副本）
- 强制类型转换产生的临时对象（如：`static_cast<double>(i)`）
- 字面常量‌（除字符串字面值外）
- `std::move` 的结果（如：`std::move(x)`，其结果是将亡值，属于右值的一种）
- ‌`Lambda` 表达式‌（生成一个唯一的闭包类对象，该对象是临时的，属于纯右值）

## 纯右值和将亡值

纯右值和将亡值都属于右值的范畴。

### 纯右值

运算表达式产生的临时变量、不和对象关联的原始字面量、非引用返回的临时变量、`Lambda` 表达式等都是纯右值。
- 除字符串字面值外的字面值
- 返回非引用类型的函数调用
- 类生成的临时对象（如：`MyClass()`）
- 后置自增自减表达式 （如：`i++`、`i--`）
- 算术表达式(如：`a+b`, `a*b`, `a&&b`, `a==b` 等)
- 取地址表达式等(如：`&a`)

### 将亡值

将亡值是 C++11 新增的，可以理解为**即将要销毁的值**，目的是告诉编译器，这个对象马上就要销毁或不再使用了，你可以直接拿走它的内部资源（如指针、内存块），而不需要进行昂贵的深拷贝。常用来完成移动构造或者移动赋值的特殊任务。
- 返回右值引用（`T&&`）的函数调用
- 转换为 `T&&` 类型转换函数的返回值（如：`static_cast<T&&>(lvalue_obj)`）
- `std::move` 函数的返回值（`std::move`的本质‌也是调用`static_cast`）

```
class A 
{
    xxx;
};

A a;
auto c = std::move(a);
auto d = static_cast<A&&>(a);
```

①、`c`、`d` 是左值，有变量名，可以取地址，生命周期持久（直到作用域结束），也可以放到等号左边。

②‌、表达式 `std::move(a)`、`static_cast<A&&>(a)` 的结果是将亡值，即右值。


## 左值引用和右值引用

它们都是引用，都是对象的一个别名，**并不拥有所绑定对象的资源**，都必须立即初始化。

```
type &name = exp; // 左值引用
type &&name = exp; // 右值引用
```

### 左值引用

左值引用分为两部分：
1. 非常量左值引用（`T&`）‌只能绑定到左值；
2. 常量左值引用（`const T&`）是“万能引用”‌：它可以绑定到‌左值‌、‌纯右值‌和‌将亡值‌。

    ```
    int a = 5;
    int& b = a; // b是左值引用

    int& c = 10; // error，10 是纯右值，不能绑定到非常量左值引用
    const int& d = 10; // ok，因为是常量左值引用，可以绑定到右值
    ```

对于非常量左值引用，赋值符号右边的值必须是左值，意味着可以取地址，如果不能取地址，则会编译失败。或者可以使用常量左值引用，但这样就只能通过引用来读取数据，不能修改数据。

### 右值引用

专门用于绑定‌右值‌（包括‌纯右值‌和‌将亡值‌）

```
int a = 4;
int &&b = a; // error, a是左值
int &&c = std::move(a); // ok 结果是将亡值属于右值的一种
```

如果使用右值引用，那赋值符号右边的值需要是右值，可以使用 `std::move` 函数强制把左值转换为右值。

## 移动语义

移动语义可以理解为转移所有权，之前的拷贝是对于别人的资源，自己重新分配一块内存存储复制过来的资源。而对于移动语义，类似于转让或者资源窃取的意思，对于那块资源，转为自己所拥有，别人不再拥有也不会再使用，通过 C++11 新增的移动语义可以省去很多拷贝负担。那怎么利用移动语义呢，为了让自定义类支持移动语义，你需要显式定义移动构造函数‌和‌移动赋值运算符（如果需要重温移动构造的部分，请见文章《类与对象》）。而移动语义的基础是‌右值引用‌（`T&&`），其是专门用于绑定右值，它允许我们识别出那些“即将被销毁”的对象，从而安全地接管其资源。

现有一个自定义的 `MyString` 类，我们简单实现了移动构造函数和一些必要的函数如下：

```
class MyString
{
public:

    // 构造函数（字符数组）
    MyString(const char* str) : length(strlen(str))
    {
        data = new char[length + 1];
        strcpy_s(data, length + 1, str);
    }

    // 析构函数
    ~MyString()
    {
        delete[] data;
        data = nullptr;
    }

    // 拷贝构造函数
    MyString(const MyString& other) : length(other.length)
    {
        data = new char[length + 1];
        strcpy_s(data, length + 1, other.data);
        std::cout << "Copy constructor called" << std::endl;
    }

    // 移动构造函数
    MyString(MyString&& other) noexcept : data(other.data), length(other.length)
    {
        other.data = nullptr;
        other.length = 0;
        std::cout << "Move constructor called" << std::endl;
    }
private:
    char* data;
    int length;
};
```

通过 `MyString` 类，应该如何触发移动语义呢？

一般有以下两种方式：
1. 编译器自动触发（最常见）

    当使用‌临时对象‌（右值）初始化或赋值时，且禁用 NRVO 后（有关 NRVO 的详情可以参见文章《编译器对函数的值传递做了什么优化》），编译器会自动触发移动语义，调用移动构造函数。

    ```
    MyString createMyString()
    {
        MyString a("Hello");
        return a;
    }

    int main()
    {
        MyString c = createMyString(); // 禁用NRVO后，也将调用移动构造函数
        return 0;
    }
    ```

2. 显式触发(`std::move`)

    当你有一个具名左值对象，但确定之后不再使用它，想强制转移其资源时，使用 `std::move`，注意 `std::move` 本身不移动数据，它只是一个类型转换辅助函数，将左值强制转换为右值引用 (`static_cast<T&&>`)，从而告诉编译器“可以调用移动构造函数/赋值运算符”。

    ```
    int main()
    {
        MyString a(10);
        MyString b = a; // 调用拷贝构造函数
        MyString d = std::move(a); // 调用移动构造函数
        // 警告：此后 a 处于“有效但未指定”状态（data 为 nullptr）
        // 不要再访问 a 的数据，但可以安全析构或重新赋值
        return 0;
    }
    ```

 如果不使用 `std::move()`，会有很大的拷贝代价，使用移动语义可以避免很多无用的拷贝，提供程序性能，自 C++11 起，STL 标准库中所有主要容器都实现了移动构造函数和移动赋值运算符，方便使用。例如：

```
std::vector<string> vecs= {"hello", "world", "cpp"};
std::vector<string> vecm = std::move(vecs); // // vecs 变空，vecm 直接拥有原来的资源，零拷贝
```

你有没有经常听说过一句话，叫做 `std::move` 不移动任何东西，明明我们使用 `std::move` 后就将资源转移给新对象了，为什么还要说 `std::move` 不移动任何东西呢？

究其原因是因为：

- 移动语义是“锁”‌：类通过提供移动构造函数或移动赋值运算符，声明自己支持“被移动”。如果类没有定义这些函数，编译器可能会回退到拷贝语义，或者禁止移动。
- `std::move` 是“钥匙”‌：默认情况下，具名变量（即使它是临时对象的名字）在 C++ 中被视为左值。左值通常绑定到拷贝构造函数。`std::move` 的作用是将这个左值转换成右值，从而匹配到移动构造函数或移动赋值运算符这把“锁”。
- `std::move` 仅仅是一个类型转换操作（Cast）。它不会改变对象的内部状态，也不会调用任何移动构造函数。真正的“移动”动作发生在后续的移动构造函数或移动赋值运算符执行时。

简单来说，‌移动语义是一种资源管理的优化策略，而 `std::move` 是一个用于触发该策略的工具函数。

**注意**：

- 移动语义针对于那些实现了移动构造函数‌和‌移动赋值运算符的类对象，通过“窃取资源指针”避免深拷贝，性能提升巨大(`O(1)VSO(n)`)。对于基本类型如 `int`、`float` 等移动语义‌退化为拷贝‌，因为基本类型没有堆内存资源可“窃取”，其值本身就存储在栈上，移动和拷贝的操作完全一致（都是寄存器或栈内存赋值）。移动语义对基本类型确实没有性能优化，但语法上依然成立；
- 如果一个类没有实现移动构造函数‌和‌移动赋值运算符，使用 `std::move` ‌**不会**‌触发移动语义，而是会‌**退化为拷贝操作**‌（调用拷贝构造函数或拷贝赋值运算符）；
- 被 `std::move` 后的对象处于‌**‌有效但未指定‌**（valid but unspecified）‌的状态。通常意味着它不再拥有原本的资源（如指针变为 `nullptr`，容器变为空），但你仍然可以对其执行析构或重新赋值等操作，‌**不应‌**再访问其原有数据；
- 如果对 `const` 对象使用 `std::move`，它会转换为 `const T&&`。由于移动构造函数通常接受非 `const` 右值引用（以便修改源对象），这往往会导致编译器选择拷贝构造函数代替移动构造函数，从而失去移动语义的性能优势。

## 完美转发

了解完美转发之前我们先理解万能引用和引用折叠的相关概念。

### 万能引用

- 发生类型推导（例如模板、`auto`）的时候，使用 `T&&` 类型表示为万能引用，否则表示右值引用。
- 万能引用类型的形参既能匹配任意引用类型的左值、右值。

也就是说编写模板函数时，只提供万能引用形参一个版本就可以匹配左值、右值，不必编写多个重载版本，如下：

```
template<class T>
void func(T&& t)
{
    return;
}
```

所谓的万能引用是因为发生了类型推导，`T&&` 和 `auto&&` 的初始化过程中都会发生类型的推导。

### 引用折叠

- 在 C++ 中，“引用的引用”是非法的。像 `auto& &rx = x;`（注意两个 `&` 之间有空格）这种直接定义引用的引用是不合法的，但是编译器在通过类型别名或模板参数推导等语境中，会间接定义出“引用的引用”，这时引用会形成“折叠”。
- 引用折叠会发生在模板实例化、`auto` 类型推导、类型别名(`typedef/using`)、以及 `decltype` 语境中。

### 引用折叠规则

1. 两条规则

    - 所有右值引用折叠到右值引用上仍然是一个右值引用。如 `X&& &&` 折叠为 `X&&`。
    - 所有的其他引用类型之间的折叠都将变成左值引用。如 `X& &`, `X& &&`, `X&& &` 折叠为 `X&`。可见左值引用会传染，沾上一个左值引用就变左值引用了。根本原因是在一处声明为左值，就说明该对象为持久对象，编译器就必须保证此对象可靠（左值）。

2. 利用引用折叠进行万能引用初始化类型推导

    - 当万能引用（`T&& param`）绑定到左值时，由于万能引用也是一个引用，而左值只能绑定到左值引用。因此，`T` 会被推导为 `T&` 类型。从而 `param` 的类型为 `T& &&`，引用折叠后的类型为 `T&`。
    - 当万能引用（`T&& param`）绑定到右值时，同理，右值只能绑定到右值引用上，故 `T` 会被推导为 `T` 类型。从而param的类型就是 `T&&`（右值引用）。

### 完美转发

当我们将一个右值引用传入函数时，他在实参中有了命名，所以继续往下传或者调用其他函数时，根据 C++ 标准的定义，这个参数变成了一个左值。那么他永远不会调用接下来函数的右值版本，这可能在一些情况下造成拷贝。

为了解决这个问题 C++11 引入了完美转发，根据右值判断的推倒，调用 `std::forward` 传出的值，若原来是一个右值，那么他转出来就是一个右值，否则为一个左值。这样的处理就完美的转发了原有参数的左右值属性(包括其CV限定符)，再根据左右值的属性，调用拷贝或者移动，这样不会造成一些不必要的性能损耗。

```
void PrintV(int &t)
{
    cout << "lvalue" << endl;
}

void PrintV(int &&t)
{
    cout << "rvalue" << endl;
}

template <typename T>
void Test(T &&t)
{
    PrintV(t);
    PrintV(std::forward<T>(t));
}

int main()
{
    Test(1); // lvalue rvalue
    int a = 1;
    Test(a);                       // lvalue lvalue
    Test(std::move(a));            // lvalue rvalue
    return 0;
}
```

分析如下：

- `Test(1)` 和 `Test(std::move(a))`：传入 `Test` 的实参是右值，模板中`T &&t` 为万能引用，根据引用折叠推导规则，`T` 被推导为 `int`（非引用），形参 `t` 的类型变为 `int&&`，在 `Test` 函数体内，当你写下 `t` 时，你是在使用一个‌拥有名字的变量‌，根据“具名即左值”规则，表达式 `t` 的值类别是‌左值（lvalue）‌，因此，当你调用 `PrintV(t)` 时，编译器看到的是左值，所以打印 `lvalue`。而调用 `PrintV(std::forward(t))` 时候，会进行完美转发，按照原来的类型转发，`std::forward<int>` 执行 `static_cast<int &&>(t)`，折叠后返回 `‌int&&`‌（右值引用）所以打印 `rvalue`。
- `Test(a)`：传入 `Test` 的实参是左值，模板中`T &&t` 为万能引用，根据引用折叠推导规则，`T` 被推导为 `int&`（左值引用），形参 `t` 的类型折叠为 `int&`，在 `Test` 函数体内，当你写下 `t` 时，你是在使用一个‌拥有名字的变量‌，根据“具名即左值”规则，表达式 `t` 的值类别是‌左值（lvalue）‌，因此，当你调用 `PrintV(t)` 时，编译器看到的是左值，所以打印 `lvalue`。而调用 `PrintV(std::forward(t))` 时候，会进行完美转发，按照原来的类型转发，`std::forward<int&>` 执行 `static_cast<int& &&>(t)`，折叠后返回 `‌int&`‌（左值引用），所以打印 `lvalue`。

结论：
`std::forward` 会根据传递给 `Test` 函数实参的左/右值类型进行转发。当传给 `Test` 函数左值实参时，`std::forward` 返回左值引用，并将该左值转发给 `PrintV(std::forward<T>(t))` 函数。而当传入 `Test` 的实参为右值时，`std::forward` 返回右值引用，并将该右值转发给 `PrintV(std::forward<T>(t))` 函数。


你是不是又听说过一句话，叫做 `std::forward` 不转发任何东西？

`std::forward` 本身不进行任何数据移动或拷贝，它仅仅是一个编译期的类型转换工具（Cast）‌，它的本质也是 `static_cast`。它只是告诉编译器：“请把在这个表达式中的这个变量，当作某种引用类型（左值或右值）来处理”。真正执行资源转移（移动）或复制（拷贝）动作的，是‌被调用的目标函数‌（如移动/拷贝构造函数或移动/拷贝赋值运算符），而不是 `std::forward` 本身。


**注意**：
- `std::forward` 仅在函数模板参数为‌万能引用‌（`T&&` 且发生类型推导）时才有意义，若参数是普通右值引用（如 `void f(int&&)`），应直接使用 `std::move`，因为此时无需保留左值语义；
- 必须显式指定模板参数 `T`，写作 `std::forward<T>(arg)`，`std::forward(arg)` 会导致编译错误，因为编译器无法自动推导 `std::forward` 的模板参数；
- 严禁多次转发同一参数，如果实参是右值，`std::forward<T>(arg)` 会将其转换为右值引用，可能触发目标函数的‌移动语义‌，移动后，源对象（arg 绑定的对象）处于‌有效但未指定‌的状态（如指针置空）；
- `std::forward` 旨在转发‌传入的参数‌，对于函数内部创建的局部变量，若希望移动其资源，应直接使用 `std::move(local_var)`；
- 始终使用推导出的模板参数 `T`，即 `std::forward<T>(arg)`。`std::forward<int>(arg)`，若 `T` 实际推导为 `int&`（左值），硬编码 `int` 会强制转为右值，导致左值实参被意外移动。

## 总结

**两者比较**

1. `std::move` 和 `std::forward` 都是仅仅执行强制类型转换的函数。`std::move` 无条件地将实参强制转换成右值。而 `std::forward` 根据模板参数 `T` 的记录，有条件地将具名变量转换回其原始的值类别（左值或右值）。
2. `std::move` 并不进行任何移动，`std::forward` 也不进行任何转发。这两者都是编译期的类型转换工具，在运行期都无所作为，它们不会生成任何可执行代码，不会修改内存，不会调用构造函数，不会移动指针。

**使用时机**
1. 针对右值引用的最后一次使用实施 `std::move`，针对万能引用的最后一次使用实施 `std::forward`。
2. 在按值返回局部对象时，‌绝对不要‌使用 `std::move` 或 `std::forward`。‌直接返回‌是让编译器优化（NRVO）的唯一正确途径。手动移动不仅多余，还会降低性能。
