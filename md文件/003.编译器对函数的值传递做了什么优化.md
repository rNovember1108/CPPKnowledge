# 编译器对函数的值传递做了什么优化

## 对象的分类

C++ 在对函数参数传递和返回值（本文主要集中讨论按值传递的场景，引用和指针除外）上有多种优化手段，核心是避免不必要的拷贝。针对不同类型的对象（主要分为两类：**简单对象**和**复杂对象**），有不同的优化方法和保持高效的使用方法。

## 简单对象

### 定义

1. 基础类型对象：`int`、`char`、`double`、`bool`、`float`、指针等；
2. 平凡小结构体/类：大小不超过特定阈值（一般来说 `Linux` 下为 16 字节，`windows` 下为 8 字节，取决于 ABI），只包含基础类型对象和平凡结构体/类成员，且没有实现复杂拷贝逻辑（无动态内存对象、无虚函数）。
    - 无构造/析构、无拷贝/移动构造、无拷贝/移动重载赋值运算符等特殊成员函数；
    - 无动态内存成员对象，如：`string`、`vector`、`list` 等；
    - 无虚函数，包括自己定义和继承而来；

**注**：虽然添加特殊成员函数会让对象失去“平凡”特性，但可以使用 `=default` 保持平凡特性，同时明确意图。

```
#include <iostream>
#include <type_traits>

// 平凡对象，使用编译器生成的默认拷贝/移动构造等函数
struct Point
{
    int x, y;
};

// 平凡对象，使用=default声明为显示默认构造函数
struct PointDefault
{
    int x, y;
    PointDefault() = default;
};

// 非平凡对象，使用自定义构造
struct PointNonTrivial
{
    int x, y;
    PointNonTrivial()  // 自定义构造
    {
    }
};

int main()
{
    std::cout << std::is_trivial_v<Point> << std::endl;                 //返回 1
    std::cout << std::is_trivial_v<PointDefault> << std::endl;          //返回 1
    std::cout << std::is_trivial<PointNonTrivial>::value << std::endl;  //返回 0
    return 0;
}
```

### 参数传递

函数参数传递时，简单对象按值传递比按引用传递略快，因为部分可能走寄存器操作，就算走栈也至少不会有间接寻址的操作（解引用）。当然，需要修改原始对象时例外，只能传引用，因为按值传递不影响外部。

```
struct Point
{
    int x , y;
};

int add(Point p)
{
    return p.x + p.y;
}

int add_ref(const Point& p)
{
    return p.x + p.y;
}
```

分别调用 `add` 函数和 `add_ref` 函数10000000次，并执行10次调用排除干扰性。

### 返回值

函数返回值时，简单对象也是通过寄存器来高效返回的。

```
// 直接返回临时对象
Point create()
{
    return {1, 2};
}

// 或者返回具名对象
Point create()
{
    Point p;
    p.x = 1;
    p.y = 2;
    return p;
}

int main()
{
    Point p = create();
    return 0;
}
```

### 速查表

| 特性 | ‌返回值 (Return Value)‌ | ‌入参 (Arguments)‌ |
| --- | --- | --- |
| ‌主要传递方式‌ | ‌寄存器‌ (只要放得下) | ‌混合‌ (寄存器 + 栈) |
| ‌`x86 (32-bit)‌` | 寄存器 (EAX:EDX) | 默认全栈 (`__cdecl`) |
| ‌`x64 (64-bit)‌` | 寄存器 (RAX, XMM0...) | 前4-6个寄存器，其余栈 |
| ‌`ARM64‌` | 寄存器 (X0, D0...) | 前8个寄存器，其余栈 |
| ‌设计哲学‌ | ‌越快越好‌ (调用者直接消费) | ‌平衡负载‌ (寄存器不够用时降级) |


## 复杂对象

### 定义

非平凡小结构体/类和超过阈值的大型结构体/类。

```
class MyClass
{
public:
    // 构造函数
    MyClass()
    {
        std::cout << "Constructor called" << std::endl;
    }

    // 析构函数
    ~MyClass()
    {
        std::cout << "Destructor called" << std::endl;
    }

    // 拷贝构造函数
    MyClass(const MyClass& other)
    {
        std::cout << "Copy constructor called" << std::endl;
    }

    // 赋值运算符重载
    MyClass& operator=(const MyClass& other)
    {
        std::cout << "Assignment operator overload called" << std::endl;
        return *this;
    }

    // 移动构造函数
    MyClass(MyClass&& other) noexcept 
    {
        std::cout << "Move constructor called" << std::endl;
    }

    // 移动赋值运算符重载
    MyClass& operator=(MyClass&& other) noexcept
    {
        std::cout << "Move assignment operator overload called" << std::endl;
        return *this;
    }
};
```

### 参数传递

复杂对象按值传递参数入参主要分为**纯右值**、**将亡值**、**左值**三大类，对每一种值有不同的情况发生：

#### 纯右值(Prvalue)‌(如 `func(MyClass())`)

```
void func(MyClass myclass)
{
}
int main()
{
    func(MyClass());
    return 0;
}
```

**注**：在 g++ 编译时，添加 `-fno-elide-constructors` 参数，可以关闭编译器构造优化，我们将看到整个函数调用全过程。

在Linux上分别通过4种形式的命令来编译并执行，得到结果如下：

![](..\images\47f02bd53d954dbfabfc1969a96eb24b.png)

- 情况1：在禁用编译器构造优化并且C++17之前（C++ 11/14），纯右值作为入参，将多执行一次移动构造，若无移动构造，调用拷贝构造；
- 情况2：不禁用编译器构造优化并且C++17之前（C++ 11/14），纯右值作为入参，编译器将做出优化，在参数位置直接构造；
- 情况3：在禁用编译器构造优化并且C++17包括之后，纯右值作为入参，将做出优化，在参数位置直接构造；
- 情况4：不禁用编译器构造优化并且C++17包括之后，纯右值作为入参，将做出优化，在参数位置直接构造；

在 C++17 之前，针对纯右值作为入参的情况，允许‌拷贝省略，编辑器将根据配置决定是否启用优化（默认启用），在C++17包括之后，将强制‌拷贝省略，不调用‌移动或拷贝构造，不管编译器是否启用优化。

#### 将亡值(Xvalue)‌(如 `func(std::move(obj))`)

```
void func(MyClass myclass)
{
}
int main()
{
    MyClass myclass;
    func(std::move(myclass));
    return 0;
}
```

在Linux上分别通过4种形式的命令来编译并执行，得到结果如下：

![](..\images\74aeedd732f042599cb523a928f0c765.png)

可以看到，将亡值作为入参时，四种情况得到的结果是一样的，调用了移动构造，它被“优化”成了移动，若无移动构造，调用拷贝构造。

#### 左值(Lvalue)‌(如 `func(obj)`)

```
void func(MyClass myclass)
{
}
int main()
{
    MyClass myclass;
    func(myclass);
    return 0;
}
```

在Linux上分别通过4种形式的命令来编译并执行，得到结果如下：

![](..\images\caff9fff396b4c7bb61109c26f3c41bf.png)

可以看到，左值作为入参时，四种情况得到的结果是一样的，调用了拷贝构造，是因为编译器必须遵守 C++ 的“语义隔离”承诺，且无法在所有情况下证明“不拷贝是安全的”。

### 返回值

复杂对象按值传递返回值跟入参一样也是分为**纯右值**、**将亡值**、**左值**三大类，对每一种值有不同的情况发生

#### 纯右值(Prvalue)‌(如 `return MyClass()`)

```
MyClass func()
{
    return MyClass();
}
int main()
{
    func();
    return 0;
}
```

在Linux上分别通过4种形式的命令来编译并执行，得到结果如下：

![](..\images\23a2ede82caa4f08a526d0fe1d64fda3.png)

- 情况1：在禁用编译器构造优化并且C++17之前（C++ 11/14），纯右值作为返回值，将多执行一次移动构造，若无移动构造，调用拷贝构造；
- 情况2：不禁用编译器构造优化并且C++17之前（C++ 11/14），纯右值作为返回值，编译器将做出优化，在接收变量位置直接构造；
- 情况3：在禁用编译器构造优化并且C++17包括之后，纯右值作为返回值，将做出优化，在接收变量位置直接构造；
- 情况4：不禁用编译器构造优化并且C++17包括之后，纯右值作为返回值，将做出优化，在接收变量位置直接构造；

在 C++17 之前，针对纯右值作为返回值的情况，允许‌拷贝省略，编辑器将根据配置决定是否启用优化（默认启用），在C++17包括之后，将强制‌拷贝省略，不调用‌移动或拷贝构造，不管编译器是否启用优化。

#### 将亡值(Xvalue)‌(如 `return std::move(obj)`)

```
MyClass func()
{
    MyClass myclass;
    return std::move(myclass);
}

{
    func();
    return 0;
}
```

#### 左值(Lvalue)‌(如 `return obj`)

MyClass func()

### 速查表

| 传入表达式类型 | C++17 之前 (C++11/14) | C++17 及之后 |
| --- | --- | --- |
| ‌纯右值 (Prvalue)‌(如 func(MyClass())) | ‌允许‌拷贝省略 若未省略：调用‌移动构造‌ 若无移动：调用‌拷贝构造‌ | ‌强制‌拷贝省略 (Mandatory Elision)‌不调用‌移动或拷贝构造 直接在参数位置‌直接构造‌ |
| ‌将亡值 (Xvalue)‌(如 func(std::move(obj))) | 调用‌移动构造‌ 若无移动：调用‌拷贝构造‌ | 调用‌移动构造‌ 若无移动：调用‌拷贝构造‌(无变化) |
| ‌左值 (Lvalue)‌(如 func(obj)) | 调用‌拷贝构造‌ | 调用‌拷贝构造‌(无变化) |


| 返回表达式类型 | C++17 之前 (C++11/14) | C++17 及之后 |
| --- | --- | --- |
| ‌纯右值 (Prvalue)‌(如 return MyClass();) | ‌允许‌拷贝省略 (RVO) 若未省略：调用‌移动构造‌ 若无移动：调用‌拷贝构造‌ | ‌强制‌拷贝省略 (Mandatory Elision)‌不调用‌移动或拷贝构造 直接在接收变量位置‌直接构造‌ |
| ‌将亡值 (Xvalue)‌(如 return std::move(obj);) | 调用‌移动构造‌ 若无移动：调用‌拷贝构造‌(阻碍 NRVO) | 调用‌移动构造‌ 若无移动：调用‌拷贝构造‌(依然阻碍 NRVO) |
| ‌左值 (Lvalue)‌(如 return obj;) | ‌尝试 NRVO‌ 若 NRVO 失败：调用‌移动构造‌ 若无移动：调用‌拷贝构造‌ | ‌尝试 NRVO‌ 若 NRVO 失败：调用‌移动构造‌ 若无移动：调用‌拷贝构造‌ |


## 其他概念

### 移动被抑制后退化
在没有移动构造的情况下，将退化成拷贝构造。当移动构造被抑制，而你又尝试 `std::move(obj)` 传参时，编译器寻找 `T(T&&)`‌，结果找不到‌（被抑制了），然后编译器寻找 `T(const T&)`， ‌找到了‌（你手写的）。右值引用（`T&&`）可以绑定到常量左值引用（`const T&`）。因为 `const T&` 承诺“我不修改你”，所以绑定的对象是右值还是左值都无所谓，反正我只读。调用拷贝构造。编译器宁愿让你慢一点（拷贝），也不愿让你出错（使用错误的默认移动逻辑）或直接编译失败（除非你强制要求移动）。为了避免这种退化和潜在的性能损失，现代 C++ 推荐遵循‌“五法则”‌，并善用 `= default`。参加第二章<<类与对象>>中关于‌“五法则‌“的介绍。

“移动被抑制”只会导致“按值传递”时的退化。‌
1. 如果是‌按值传递‌：
    - 有拷贝 -> 退化为拷贝。
    - 无拷贝 -> 编译报错。
2. 如果是‌按引用传递‌：
    - 无论移动是否被抑制，都不会触发构造函数的调用，因此不存在“退回拷贝”的说法。

### 拷贝省略

拷贝省略（Copy Elision）是C++中编译器主动省略对象拷贝/移动构造过程的优化机制，核心是直接在目标内存位置构造对象，彻底消除不必要的临时对象创建。RVO（返回值优化）和NRVO（命名返回值优化）就是这种优化在函数返回值场景下的具体应用：

1. **RVO（返回值优化）**：针对函数返回‌匿名临时对象‌的场景，编译器直接将返回对象构造在调用方的目标内存位置，完全省略拷贝步骤。例如 `MyClass func() { return MyClass(); }` 这种写法就会触发RVO；
2. **NRVO（命名返回值优化）**：是RVO的扩展，针对函数返回‌具名局部对象‌的场景（例如 `MyClass func() { MyClass obj; return obj; }`），满足条件时同样可以直接在调用端构造对象，省略拷贝。不过NRVO的触发条件更严格，多返回路径会增加优化失败概率，且不强制要求编译器实现。

关于标准规定：在C++17标准之后，针对纯右值（prvalue）的RVO已经被强制要求启用，编译器必须执行拷贝省略；而NRVO仍然依赖编译器的智能分析，不属于强制要求。

### 禁用标志

以上都是在Linux下g++执行，Windows下MSVC也拥有类似的标识，不过自由度不高，见如下：

| 编译器 | 标志 | 禁用 RVO (返回临时对象) | 禁用 NRVO (返回局部变量) | ‌禁用入参优化 (传入临时对象)‌ |
| --- | --- | --- | --- | --- |
| ‌GCC / Clang‌ | -fno-elide-constructors | ✅ 是 | ✅ 是 | ‌✅ 是‌ |
| ‌MSVC‌ | /Zc:nrvo- | ❌ 否 | ✅ 是 | ‌❌ 否‌ |

## 总结

1. 平时我们在使用高级编译器的时候，针对函数按值传递情况下的入参和返回值数据时，并不是不调用默认函数，而是编译器和语言做了优化。
2. 值传递模式下如果一个类里没有显式实现移动构造函数与移动赋值运算符重载函数，将调用拷贝构造函数与赋值运算符重载函数。拷贝函数与移动函数都存在的情况下，将优先使用移动函数，避免大数据拷贝。
3. 函数入参在值传递时，将根据情况调用拷贝/移动构造函数或者直接构造。在引用传递时，不调用任何函数。
4. 函数返回引用类型时，不能返回局部对象的引用；同样道理，也不应该返回指向局部对象的指针。
5. 简单对象按值传递入参时使用寄存器或者栈传递值，复杂对象按值传递入参时使用栈传递大块内存拷贝以创建独立副本，所以针对简单对象，直接使用值传递，针对复杂对象，还是使用引用、指针等操作更高效。
