# 内存布局与特殊变量初始化时机

## 内存布局

程序由指令和数据构成，指令和数据又存储在不同的段内，程序分段有利于区分指令和数据，指令通常是只读的，数据是可读写或只读的，分到不同的段内，设置不同的权限，可以防止程序指令被无意修改。一个程序编译后的分段内存布局可能如下所示（用户空间）：

```
高地址 (High Address)
+--------------------------------------------------+
|               命令行参数和环境变量                 |
+--------------------------------------------------+
|                   栈 (Stack)                     |  ⬇️ 向低地址生长
|      (局部变量、函数参数、返回地址、上下文信息)      |
|                                                  |
|                  (空闲空间 / Gap)                 |  <-- 栈和堆在此相遇
|                                                  |
+--------------------------------------------------+
|                   堆 (Heap)                      |  ⬆️ 向高地址生长
|        (动态内存分配: malloc, new)                |
+--------------------------------------------------+
|                 BSS 段 (.bss)                    |  (未初始化全局/静态变量)
+--------------------------------------------------+
|                 数据段 (.data)                   |  (已初始化全局/静态变量)
+--------------------------------------------------+
|               只读数据段 (.rodata / .rdata)      |  (字符串常量、const全局变量)
+--------------------------------------------------+
|                 代码段 (.text)                   |  (机器指令、函数代码)
+--------------------------------------------------+
低地址 (Low Address)
```

可以看到，程序被分成了七个主要的内存区域。因为代码指令、数据段等往往是固定大小的，所以处于低地址；堆栈可能会在程序执行时动态增长，所以处于高地址。同时，不同段的数据还代表着不同的存储时期。

**注：以上从低地址到高地址的内存布局分布，只是教学用的简化抽象描述‌，实际运行代码会发现，现代 C++ 程序的栈不一定位于用户空间最顶部，是因为操作系统采用地址空间布局随机化（ASLR）和动态虚拟内存管理，而非固定布局。‌‌因此，C++ 本身不定义内存布局，它依赖底层平台的 ABI 和 OS 虚拟内存管理策略，实际布局是‌运行时动态、随机化、非固定的‌，远比以上的静态图复杂。‌‌**


## 存储时期

C++ 中不同的数据存在四个存储时期，分别为 `automatic`,`static`,`thread` 和 `dynamic`:

- `automatic` 绝大多数情况下主要指的就是栈上的数据，它能够在进入某个作用域时自动申请内存，并在离开时自动释放内存。
- `static` 指的主要是 `.data` 和 `.bss` 的静态存储期的数据，这些数据在‌加载期‌（Load Time）就为 `.data` 和 `.bss` 预留了虚拟内存空间，等到程序结束时才释放。
- `thread` 存储时期是 C++11 才有的，只有 `thread_local` 修饰的数据才属此类，它们在线程开始时申请内存，线程结束时释放内存。
- `dynamic` 则表示堆上的数据，也就是使用 `new` 或者 `malloc` 申请的内存，这些内存必须手动释放。当然，通过智能指针这些数据的生命周期也能够自动管理。

## 全局变量初始化

C++ 标准保证全局变量在 `main` 函数执行之前完成初始化。但这个过程在底层实现上分为两个截然不同的阶段：**静态初始化**和**动态初始化**，即 `Static initialization` 和 `Dynamic initialization`。

### 静态初始化(Static initialization)

静态初始化发生在**编译期**或**程序加载期**‌。编译器在编译时就能确定变量的初始值，因此不需要在运行时执行额外的指令来“计算”这个值。它又细分为两种情况：**零初始化**(`Zero Initialization`)和**常量初始化**(`Constant Initialization`)‌。

#### 零初始化（Zero Initialization）

- 对象‌：未显式初始化的全局变量，或显式初始化为 `0`/ `nullptr` / `false` 的变量。
- 行为‌：内存被清零。
- ‌内存段‌：‌`.bss` 段‌。
- ‌特点‌：不占用可执行文件（ROM/磁盘）的空间，只在程序加载到内存时分配空间并清零。
- 示例‌：

```
int g_uninit;      // 未显式初始化，放在 .bss
static int g_zero = 0; // 值为 0，放在 .bss
```

#### 常量初始化（Constant Initialization）

- 对象‌：使用常量表达式（`constexpr`）初始化的基本类型或 POD（Plain Old Data）结构。
- ‌行为‌：初始值直接硬编码在可执行文件中。
- ‌内存段‌：‌`.data` 段‌（如果可读可写）或 ‌`.rodata` 段‌（如果为 `const`）。
- ‌特点‌：占用可执行文件空间。程序加载时，操作系统直接将文件中的值拷贝到内存对应地址。
- ‌示例‌：

```
int g_init = 42;       // 值为 42，放在 .data
const int g_const = 10; // 值为 10，放在 .rodata
```

### 动态初始化(Dynamic initialization)

动态初始化发生在‌**运行时‌**，但在 `main` 函数执行‌之前‌。它需要执行具体的代码（如构造函数、函数调用）来计算初始值。

- ‌对象‌：

    - 类类型的全局/静态对象（需要调用构造函数）。
    - 初始值依赖于函数调用的变量（如 `int g_val = getValue();`）。
    - 非 `constexpr` 的复杂表达式初始化。

- ‌行为‌：由 C++ 运行时库（CRT）在启动例程（Startup Routine）中调用相应的初始化代码。
- ‌内存段‌：最终数据依然存放在 ‌`.data‌` 或 ‌`.bss‌`（如果构造后结果为 `0` 且编译器优化允许，但通常类对象在 `.data`），但‌初始化过程‌本身是代码执行。
- ‌特点‌：

    - ‌有执行代码‌：会生成调用构造函数或初始化函数的机器指令。
    - 可调试‌：你可以在全局对象的构造函数或初始化函数处设置断点，调试器‌可以停住‌。
    - ‌顺序问题‌：同一编译单元（.cpp文件）内按定义顺序初始化；‌不同编译单元之间初始化顺序未定义‌（这是著名的 "Static Initialization Order Fiasco" 问题）。
- ‌示例‌：

```
#include <iostream>

class MyClass
{
public:
    MyClass() { std::cout << "Constructor called\n"; }
};

MyClass g_obj; // 动态初始化：在 main 之前调用构造函数

int getVal()
{
    return 100;
}

int g_dyn = getVal(); // 动态初始化：在 main 之前调用 getVal()
```

### 初始化顺序

C++ 标准严格规定了这两个阶段的先后顺序：

1. ‌零初始化‌ (所有静态存储期变量先清零)；
2. ‌常量初始化‌ (静态初始化的一部分，编译期确定值的变量)；
3. ‌动态初始化‌ (运行时执行代码初始化)；
4. `‌main` 函数执行‌。

**‌重要结论‌**：所有的静态初始化（零初始化 + 常量初始化）一定在所有动态初始化‌之前‌完成。


## 类的静态成员初始化

C++ 标准规定，`const` 的静态成员可以直接在类内进行初始化，而非 `const` 的静态成员需要在类外声明以初始化，对于后一种情况，我们一般选择在类的实现文件中初始化。至此，具体的初始化方式和上面说的是一致的，可以是静态初始化，也可以是动态初始化。

## 局部静态变量初始化

静态局部变量的内存空间在程序加载时就已经规划好（位于静态存储区），但其初始化代码（构造函数或赋值操作）是在程序执行流第一次到达该声明语句时才执行。
