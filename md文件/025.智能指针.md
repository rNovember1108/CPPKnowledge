# 智能指针

## C++11 智能指针

### 原始指针的问题

原始指针的问题大家都懂，就是如果忘记删除，或者删除的情况没有考虑清楚，容易造成悬挂指针(dangling pointer)或者说野指针(wild pointer)。我们看个简单的例子：

```
objtype *p = new objtype();
p->func();
delete p;
```

上面的代码结构是我们经常看到的。里面的问题主要有以下两点：
1. 代码的最后，忘记执行 `delete p` 的操作。
2. 第一点其实还好，比较容易发现也比较容易解决。比较麻烦的是，如果 `func()` 中有异常，`delete p` 语句执行不到，这就很难办。有的同学说可以在 `func()` 中进行删除操作，理论上是可以这么做，但实际操作起来，会非常麻烦也非常复杂。

此时，使用智能指针就可以方便我们控制指针对象的生命周期。在智能指针中，一个对象什么情况下被析构或被删除，是由指针本身决定的，并不需要用户进行手动管理，是不是瞬间觉得幸福感提升了一大截，有点幸福来得太突然的意思，终于不用我自己手动释放指针了。

### 什么是智能指针

从比较简单的层面来看，智能指针是RAII(Resource Acquisition Is Initialization，资源获取即初始化)机制对普通指针进行的一层封装。这样使得智能指针的行为动作像一个指针，本质上却是一个对象，这样可以方便管理一个对象的生命周期。

在 C++ 中，智能指针一共定义了四种：

```
std::auto_ptr
std::unique_ptr
std::shared_ptr 
std::weak_ptr
```

### std::auto_ptr

其中，`std::auto_ptr` 在C++11已被废弃，但仍可使用（编译时会警告），在C++17中已经移除不可用，无法编译。究其原因是因为`std::auto_ptr` 有严重的所有权转移语义缺陷，请看如下示例：

```
std::auto_ptr<int> p1(new int(5));
std::auto_ptr<int> p2 = p1;  // p1 现在变为 nullptr，p1 不再拥有对象，如果再使用 p1 会导致未定义行为
```

这种拷贝即转移的行为违反了常规的拷贝语义，非常容易引发 bug。它使用移动语义的方式很原始，在 C++11 引入真正的移动语义（`std::move`）后，`std::auto_ptr` 彻底失去存在价值。

### std::unique_ptr

`std::unique_ptr` 是独享被管理对象指针所有权(owership)的智能指针。`std::unique_ptr` 对象封装一个原始指针，并负责其生命周期。当该对象被销毁时，会在其析构函数中删除关联的原始指针。创建 `std::unique_ptr` 示例如下:

```
#include <iostream>

int main() 
{
    std::unique_ptr<int> p1(new int(5));
    std::unique_ptr<int> p2 = std::make_unique<int>(5); // 推荐使用
    std::cout << *p1 << *p2 << std::endl;
    return 0;
}
```

`std::unique_ptr` 的拷贝构造函数和拷贝赋值运算符被显式删除（`= delete`），因为它独占所有权，不允许复制，以下示例会报错：

```
int main()
{
    std::unique_ptr<int> p = std::make_unique<int>(5);
    std::cout<< *p<< std::endl;
    std::unique_ptr<int> p2(p);
    std::unique_ptr<int> p3 = p;
    return 0;
}
```

 对于 `p2`,`p3` 对应的行，IDE会提示报错

```
error C2280: “std::unique_ptr<int,std::default_delete<int>>::unique_ptr(const std::unique_ptr<int,std::default_delete<int>> &)”: 尝试引用已删除的函数
```

虽然不支持普通的拷贝和赋值操作，但却可以将所有权进行转移，使用 `std::move` 方法即可，如下示例：

```
int main()
{
    std::unique_ptr<int> p = std::make_unique<int>(5);
    std::unique_ptr<int> p2 = std::move(p);
    // std::cout<< *p << std::endl;  //此时p指针为nullptr, 解引用空指针,未定义行为
    std::cout<< *p2<< std::endl;
    return 0;
}
```

`std::unique_ptr` 最常见的使用场景，就是替代原始指针，为动态申请的资源提供异常安全保证。

```
std::unique_ptr<objtype> p = std::make_unique<objtype>();
p->func();
```

此时我们只要 `std::unique_ptr` 创建成功，`std::unique_ptr` 对应的析构函数都能保证被调用，即使发生异常，析构函数也会在栈展开（stack unwinding）过程中被调用，从而保证申请的动态资源能被释放掉。

### std::shared_ptr

我们提到的智能指针，很大程度上就是指的 `std::shared_ptr`，`std::shared_ptr` 也在实际应用中广泛使用。它的原理是使用强引用计数（关于引用计数，文章后续会详细讲解）实现对同一块内存的多个引用。在最后一个引用被释放时，指向的内存才释放，这也是和 `std::unique_ptr` 最大的区别。当对象的所有权需要共享(share)时，`std::shared_ptr` 可以进行赋值拷贝。`std::shared_ptr` 使用强引用计数，每一个 `std::shared_ptr` 的拷贝都指向相同的内存。每使用他一次，内部的强引用计数加1，每析构一次，内部的强引用计数减1，当减为0时，释放所指向的堆内存。创建 `std::shared_ptr` 示例如下：

```
int main()
{
    std::shared_ptr<int> p1(new int(1));
    std::shared_ptr<int> p2 = std::make_shared<int>(1); // 推荐使用
    std::cout << *p1 << *p2 << std::endl;
    return 0;
}
```

由于`std::shared_ptr`是共享的，所以跟`std::unique_ptr`不同，它可以进行赋值拷贝，只是强引用计数会增加1。也可以使用移动语义（`std::move`），引用计数不会增加。以下代码可以正常使用：

```
int main()
{
    std::shared_ptr<int> p = std::make_shared<int>(1);
    std::shared_ptr<int> p2(p);
    std::shared_ptr<int> p3 = p;
    std::shared_ptr<int> p4 = std::move(p); // 移动语义, 引用计数不会增加, 此时p指针为nullptr
    std::cout << *p2 << *p3 << *p4 << std::endl;
    return 0;
}
```

**使用注意点**：
1. 不能将一个原始指针初始化多个 `std::shared_ptr`，请看以下示例：

    ```
    int main()
    {
        int* p = new int(1);
        std::shared_ptr<int> p1(p);
        std::shared_ptr<int> p2(p);
        std::cout << *p << *p1 << *p2 << std::endl;
        return 0;
    }
    ```

    上面代码运行后会崩溃，原因也很简单，因为 `p1`,`p2` 都要进行析构删除，这样会造成原始指针 `p` 被双重释放。

2. 循环引用问题
    `std::shared_ptr` 最大的坑就是循环引用。请看如下例子：

    ```
    struct Son;
    struct Father
    {
        std::shared_ptr<Son> son;
    };

    struct Son
    {
        std::shared_ptr<Father> father;
    };

    int main()
    {
        auto father = std::make_shared<Father>();
        auto son = std::make_shared<Son>();

        father->son = son;
        son->father = father;

        return 0;
    }
    ```

    该部分代码会有内存泄漏问题。原因是：

    - `main` 函数退出之前，`Father` 和 `Son` 对象的强引用计数都是 `2`。
    - `son` 指针销毁，这时 `Son` 对象的强引用计数是 `1`。
    - `father` 指针销毁，这时 `Father` 对象的强引用计数是 `1`。
    - 由于 `Father` 对象和 `Son` 对象的强引用计数都是 `1`，这两个对象都不会被销毁，从而发生内存泄露。

3. 为避免循环引用导致的内存泄露，就需要使用到下一节提到的`std::weak_ptr`。

### std::weak_ptr

`std::weak_ptr` 是 C++11 引入的一种智能指针，用于解决 `std::shared_ptr` 的循环引用问题。它是对 `std::shared_ptr` 所管理对象的非拥有型（弱引用）观察者。也就是说，让 `std::weak_ptr` 指向 `std::shared_ptr` 所指向对象，对象的强引用计数并不会增加，而是增加弱引用计数。构造与初始化示例如下：

```
auto shared = std::make_shared<int>(42);
std::weak_ptr<int> weak(shared);  // 通过 shared_ptr 构造 weak_ptr
```

访问时必须通过 `lock()` 获取临时 `std::shared_ptr` 后访问，`std::weak_ptr` 没有重载 `->` 和 `*` 操作符。并且应尽早 `lock()` 并持有返回的 `std::shared_ptr`并对返回的 `std::shared_ptr` 判空后再操作。避免长期持有的`std::weak_ptr`失效。因为 `std::weak_ptr` 指向的对象可能在任意时刻被销毁。如果直接解引用，会导致未定义行为。

```
int main()
{
    auto p = std::make_shared<int>(42);
    std::weak_ptr<int> p1(p);  // 通过 shared_ptr 构造 weak_ptr

    if (auto temp_shared = p1.lock())    // 尝试提升为 shared_ptr
    { 
        // 资源存在时安全访问
        std::cout << *temp_shared;
    }
    else
    {
        std::cout << "资源已释放";
    }
    return 0;
}
```

使用 `std::weak_ptr` 就能解决前面提到的循环引用的问题，方法很简单，只要让 `Son` 或者 `Father` 包含的 `std::shared_ptr` 任意一方改成 `std::weak_ptr` 就可以了。

```
struct Son;
struct Father
{
    std::shared_ptr<Son> son;
};

struct Son
{
    std::weak_ptr<Father> father;
};

int main()
{
    auto father = std::make_shared<Father>();
    auto son = std::make_shared<Son>();

    father->son = son;
    son->father = father;

    return 0;
}
```

该部分代码区别于`std::shared_ptr`的那部分代码，不会有内存泄漏问题。原因是：

- `main` 函数第1、2行分别创建 `father` 和 `son`， 两个对象的强引用计数和弱引用计数都是 `1`（弱引用计数指控制块内部计数,`std::shared_ptr` 存活时它初始为 1）。
- `father->son = son`，`father` 对象的 `son` 成员（`std::shared_ptr`）指向 `son` 对象，`son` 的强引用计数加1，变为2。
- `son->father = father`，`son` 对象的 `father` 成员（`std::weak_ptr`）指向 `father` 对象，`father` 的强引用计数不变依然为1，而弱引用计数加1，变为2。
- `main` 函数结束，son变量销毁，此时强引用计数减1，但仍然被 `father->son` 持有，不会被销毁。
- `father` 对象销毁，此时强引用计数减1，变为0，对象被销毁。
- father对象销毁触发连锁反应，成员`son` 对象的强引用计数减1，变为0，对象被销毁。两个对象都被完全销毁。

**最佳实践**

1. ​始终通过 `lock()` 访问资源，避免使用 `expired()` 单独判断有效性，对返回的 `std::shared_ptr` 判空后再操作。
2. ​优先使用 `std::make_shared`，避免裸指针初始化导致的分离内存分配。
3. 避免跨线程传递 `std::weak_ptr` 的时效性假设，即使 `lock()` 成功，资源可能在后续代码中失效，需设计重试机制。
4. 限制生命周期

    ```
    {
        // 确保 shared 存活期间使用 weak
        auto shared = std::make_shared<Resource>();
        std::weak_ptr<Resource> weak(shared);
        // todo: 使用 weak 访问资源
    }
    // todo: 其他操作， shared 析构后，weak 自动失效
    ```

### 进阶使用

#### 创建方法

在上面 `std::unique_ptr` 和 `std::shared_ptr` 的创建方法讲述中，我们总是提到一个推荐使用的创建方法，如下所示：

```
std::unique_ptr<int> p1(new int(5));
std::unique_ptr<int> p2 = std::make_unique<int>(5); // 推荐使用

std::shared_ptr<int> p1(new int(1));
std::shared_ptr<int> p2 = std::make_shared<int>(1); // 推荐使用
```

需要注意的是，除非有极其特殊的原因，否则应该优先使用 `std::make_unique` 和 `std::make_shared`，假设你有这样一个函数调用：

```
func(std::unique_ptr<int>(new int(5)), may_throw_exception());
// 或者
func(std::shared_ptr<int>(new int(5)), may_throw_exception());
```

C++ 标准中，函数参数的求值顺序是不确定的（C++17 之前是未指定的）。可能的执行顺序是：

1. `new int(5)`（分配内存）
2. `may_throw_exception()`（抛出异常）
3. 构造 `std::unique_ptr` 或者 `std::shared_ptr`（接管内存）

如果第 2 步抛出了异常，那么第 1 步分配的内存就永远无法被释放，造成了内存泄漏。而 `std::make_unique` 和 `std::make_shared` 将内存分配和对象构造封装在了一个函数内部，确保了这两步的原子性，无论后续是否发生异常，内存都已经被智能指针安全托管。

#### 自定义删除器（Deleter）

`std::unique_ptr` 和 `std::shared_ptr` 都支持自定义删除器，用于在智能指针析构时执行自定义操作，主要用于管理非 `new/delete` 分配的资源，包括文件、套接字、句柄关闭、三方库资源释放、条件性释放等等。

```
// 函数指针方式
void deleter1(int* p) { delete p; }
std::unique_ptr<int, decltype(&deleter1)> ptr1(new int(5), deleter1);

// 可调用对象方式（lambda）
auto deleter2 = [](int* p) { delete p; };
std::unique_ptr<int, decltype(deleter2)> ptr2(new int(5), deleter2);

// 函数指针方式
void deleter1(int* p) { delete p; }
std::shared_ptr<int> ptr1(new int(5), deleter1);

// 可调用对象方式（lambda）
auto deleter2 = [](int* p) { delete p; };
std::shared_ptr<int> ptr2(new int(5), deleter2);
```

1. 从代码可以看出两者的自定义删除器的使用方式是不同的。`std::shared_ptr` 的删除器类型不是模板参数，而 `std::unique_ptr` 是模板参数。当然他们都拥有自己的默认删除器。
2. `std::unique_ptr` 的删除器是类型的一部分，零开销，类型安全。`std::shared_ptr` 的删除器不是类型的一部分，灵活但稍慢。
3. 都用 `new` 构造，`std::make_*` 不支持删除器
4. 强烈建议删除器不要抛异常（析构过程中抛异常会导致 `std::terminate()`）。

#### 引用计数

引用计数分为**强引用计数**和**弱引用计数**，它们不属于任何特定的 `std::shared_ptr` 或 `std::weak_ptr` 本身，它们属于控制块（Control Block）。`std::shared_ptr` 或 `std::weak_ptr` 只是持有指向控制块的指针。控制块是动态分配的独立对象，由所有相关的多个智能指针共享。

![](..\images\83492f988fe4442485d410be6337301e.png)

`std::shared_ptr` 存储指针（对象指针 + 控制块指针），`std::weak_ptr` 存储控制块指针（不存储对象指针）。控制块的生命周期由强引用计数和弱引用计数共同决定（即当强引用计数和弱引用计数都为 0 时，控制块被销毁，谨防控制块内存泄漏）。如下代码所示：

```
class Data
{
public:
    Data()
    {
        std::cout << "Data created" << std::endl;
    }

    ~Data()
    {
        std::cout << "Data destroyed" << std::endl;
    }
};

int main()
{
    std::cout << "=== 步骤 1: 创建 shared_ptr ===" << std::endl;
    auto sp = std::make_shared<Data>();
    // strong_count = 1, weak_count = 1（控制块自身）

    std::cout << "\n=== 步骤 2: 创建 weak_ptr ===" << std::endl;
    std::weak_ptr<Data> wp = sp;
    // strong_count = 1, weak_count = 2（控制块 + wp）

    std::cout << "\n=== 步骤 3: 销毁 shared_ptr ===" << std::endl;
    sp.reset();
    // 手动 reset(),strong_count = 0 → 对象销毁
    // weak_count = 2（控制块仍然存在）
    std::cout << "wp.expired(): " << wp.expired() << std::endl;  // 1

    std::cout << "\n=== 步骤 4: 销毁 weak_ptr ===" << std::endl;
    wp.reset();
    // 手动 reset(),weak_count = 1（只剩控制块自身）

    std::cout << "\n=== 步骤 5: 程序结束 ===" << std::endl;
    // weak_count = 0 → 控制块销毁

    return 0;
}
```

### 总结

1. 如果程序要使用多个指向同一个对象的指针，应选择 `std::shared_ptr`。这样的情况包括:

    - 有一个指针数组，并使用一些辅助指针来标示特定的元素，如最大的元素和最小的元素；
    - 两个对象都包含指向第三个对象的指针；
    - STL 容器包含指针。很多 STL 算法都支持复制和赋值操作，这些操作可用于 `std::shared_ptr`，但不能用于 `std::unique_ptr`（编译器发出 warning 甚至 error）和 `std::auto_ptr`（行为不确定）。

2. 如果程序不需要多个指向同一个对象的指针，则可使用 `std::unique_ptr`。如果函数使用 `new` 分配内存，并返还指向该内存的指针，将其返回类型声明为 `std::unique_ptr` 是不错的选择。这样，所有权转让给接受返回值的 `std::unique_ptr`，而该智能指针将负责调用 `delete`。
3. 如果使用 `std::shared_ptr` 发生了循环引用，就需要使用到 `std::weak_ptr`。将 `std::shared_ptr` 任意一方改成 `std::weak_ptr` 就可以。
