# 静态联编和动态联编

在 C++ 中，联编指的是把函数调用与具体的函数实现关联起来的过程。根据关联发生的时机不同，分为**静态联编**和**动态联编**。

## 静态联编

静态联编也叫早期联编，在编译阶段就确定了调用哪个函数。其特点是**由编译期决定**、**效率高（无需运行时查找）**、**通过普通函数调用、重载函数、非虚函数实现**，是 C++ 默认的联编方式。

1. 普通函数调用

    ```cpp
    void func()
    {
        std::cout << "func()" << std::endl;
    }

    int main()
    {
        func();
        return 0;
    }
    ```

    以上代码实现了一个普通函数调用，编译器在编译期就知道要调用哪个函数，直接生成一条调用指令，目标地址在链接阶段就被填好。

2. 非虚函数实现

    ```cpp
    class Base
    {
    public:
        void print()  // 非虚函数
        {
            std::cout << "Base::print()" << std::endl;
        }
    };

    class Derived : public Base
    {
    public:
        void print()
        {
            std::cout << "Derived::print()" << std::endl;
        }
    };

    int main()
    {
        Base* p = new Derived();

        // 输出：Base::print()
        // 静态联编，看指针类型
        p->print();
        return 0;
    }
    ```

    以上代码实现了一个普通继承中的非虚函数成员 `print()`，对于成员函数，编译器会隐式传入 `this` 指针，`p` 的静态类型 `Base*` 决定调用 `Base::print()`。调用目标写死在指令里，运行时无需任何查找，这一点跟包含了虚函数的继承有显著差别。

3. 重载函数实现

    ```cpp
    void func(int x);
    void func(double x);

    func(10);     // 编译期就确定调用 func(int)
    func(3.14);   // 编译期就确定调用 func(double)
    ```

    以上代码实现了两个重载函数 `func`，一个整数参数，一个双精度参数。重载在编译期通过**名称修饰**（Name Mangling）区分，编译器根据实参类型在编译期就选好了修饰名，链接时直接解析到对应地址。

## 动态联编

动态联编也叫晚期联编，在运行阶段才确定调用哪个函数。其特点是**由运行期决定**、**有一定运行时开销（虚函数表 `vtable` 查找）**、**通过虚函数（`virtual`） + 指针/引用实现**。

动态联编是 C++ 多态的核心，底层依赖两个东西：
1. 虚函数表（`vtable`）：每个含虚函数的类一张，存放该类虚函数的实际地址。
2. 虚表指针（`vptr`）：每个对象内部一个隐藏指针，指向所属类的 `vtable`。

```cpp
class Base
{
public:
    virtual void print()  // 虚函数
    {
        std::cout << "Base::print()" << std::endl;
    }
};

class Derived : public Base
{
public:
    virtual void print() override
    {
        std::cout << "Derived::print()" << std::endl;
    }
};

int main()
{
    Base* p = new Derived();

    // 输出：Derived::print()
    // 动态联编，运行时通过 vptr 找到实际函数地址。
    p->print();
    return 0;
}
```

以上代码实现了一个多态继承中的虚函数成员 `print()`，运行时根据 `p` 指向的实际对象类型（`Derived`）调用 `Derived::print()`（关于虚函数表和虚表指针的详细介绍，请参见[类的继承](014.类的继承.md)）。

## 对比

1. 如何区分静态联编和动态联编？

    从上面几个示例的代码中，我们选择普通继承中的非虚函数成员 `print()` 和多态继承中的虚函数成员 `print()` 这两段相关代码，来对比一下静态联编和动态联编的区别。从代码上看，实现动态联编的方式只是在类继承中添加了虚函数，其他代码都没有改变。我们分别查看这两个示例的汇编代码，有效部分截图如下：

    ![](..\images\399b87eb60264870a14c4f0957e7171c.png)

    我们解析一下这两个示例的汇编代码分别如下：

    ```cpp
    28 :     p->print();   // 动态联编，运行时通过 vptr 找实际函数
    mov  eax, DWORD PTR _p$[ebp]   ; eax = p
    mov  edx, DWORD PTR [eax]      ; edx = *p = vptr（虚表指针）
    mov  esi, esp                  ; 保存 esp（Debug 栈检查）
    mov  ecx, DWORD PTR _p$[ebp]   ; ecx = p  → this
    mov  eax, DWORD PTR [edx]      ; eax = *vptr = vtable[0]（真正的函数地址）
    call eax                       ; 间接调用
    cmp  esi, esp                  ; 检查调用前后栈是否平衡
    call __RTC_CheckEsp
    npad 1

    28 :     p->print(); // 静态联编，函数地址已知
    mov  ecx, DWORD PTR _p$[ebp]   ; ecx = p  → 准备 this
    call ?print@Base@@QAEXXZ       ; 直接调用 Base::print
    ```

    可以看到，静态联编是直接调用 `Base::print()`，而动态联编是通过虚表指针 `vptr` 找到实际函数地址（例子中从 `eax` 寄存器中获取），再调用。这是动态联编的核心所在。

2. 为什么只有通过指针或引用调用虚函数才会触发动态联编？

    动态联编要解决的问题是：函数调用时，到底应该执行哪个类的版本。指针和引用是唯一让"实际类型"在编译期变得不确定的载体。

    ```cpp
    // 编译期就知道 d 是 Derived
    Derived d;
    d.print();
    ```

    这里 `d` 是一个具体对象，它的类型在编译期是完全确定的（即是 `Derived`）。即使 `print()` 是虚函数，编译器也知道：`d` 的内存布局就是 `Derived` 的布局，`d` 的 `vptr` 一定指向 `Derived` 的 `vtable`，所以 `d.print()` 一定调用 `Derived::print()`。编译器可以直接生成 `call Derived::print`，根本不需要查表。这甚至有个专门的名字：去虚化（devirtualization）。

    而指针以及引用的方式，其类型是不确定的，如下：

    ```cpp
    // 可能返回 Base*，也可能指向 Derived
    Base* p = getObject();
    p->print();
    ```

    指针 `p` 的静态类型是 `Base*`，但它指向的对象的实际类型可能是任何 `Base` 的派生类。编译器在编译期无法知道 `p` 到底指向谁，因为它可能是运行时才创建的、可能来自外部输入、可能在不同的代码路径下被赋不同的值，这种**指向对象的实际类型不确定**正是动态联编存在的理由。编译器只能这样处理：生成一段代码，在运行时通过 `p` 指向对象的 `vptr` 找到 `vtable`，再从表中取出实际函数地址来调用。而引用的底层实现本质就是指针，类型不确定性与指针完全相同。

3. 结合虚函数表和虚表指针，探讨动态联编的实现机制。

    前面的文章我们详细介绍过虚函数表和虚表指针的作用，一起来看一个有趣的例子：

    ```cpp
    class Test
    {
    public:
        Test()
        {
            // 1. 使用 memset 将 this 对象初始化为0
            memset(this, 0, sizeof(Test));
            std::cout << "Test constructor" << std::endl;
        }

        // 2. 虚函数
        virtual void virFunc()
        {
            std::cout << "virtual func" << std::endl;
        }

        // 3. 普通函数
        void func()
        {
            std::cout << "normal func" << std::endl;
        }

        // 4. 虚析构函数
        virtual ~Test()
        {
            std::cout << "Test destructor" << std::endl;
        }

    private:
        int x = 10;
    };
    ```

    **注意：对含有虚函数的对象使用 `memset(this, 0, sizeof(Test))` 在 C++ 标准中属于未定义行为，下文的崩溃现象是 MSVC 等具体编译器实现下的表现。此处仅用于演示虚表指针的作用机制，实际工程中切勿这样写。**

    代码中我们使用注释标明了 4 点需要关注的地方，请着重关注这 4 点。现有以下两段调用的代码：

    ```cpp
    // 使用 Test 对象调用
    int main()
    {
        Test t;
        t.virFunc();
        t.func();

        return 0;
    }

    // 使用 Test 指针调用
    int main()
    {
        Test* p = new Test;
        p->virFunc();
        p->func();
        delete p;

        return 0;
    }
    ```

    分别运行会出现以下几种情况：

    ① 使用对象的方式来进行调用，运行结果正常，每个函数的调用都正常进入。

    ② 使用指针的方式来调用虚函数 `virFunc()` 时，崩溃。

    ③ 使用指针的方式来调用普通函数 `func()` 时，正常。

    ④ 释放指针 `p` 时，崩溃。

    为什么会出现上述情况呢？

    根据以往篇章我们对虚函数和虚表指针的介绍，我们可以知道：编译器在编译期就为每个多态类生成虚函数表及重定位信息，那么对于上面代码中的虚函数 `virFunc()` 和虚析构函数 `~Test()` 来说，它们在虚函数表中对应的槽位在编译时就已经确定（槽中先存放重定位项，函数的最终地址在链接/程序加载时才填入）。在实例化对象的时候，编译器会在构造函数中插入一些代码，这些代码用来给虚表指针赋值，且这些操作都发生在执行构造函数体之前；而在构造函数体中又调用 `memset()` 函数将整个对象初始化为 0，这导致虚表指针也被置为了 0，将不能通过虚表指针去查找对应的虚函数地址。

    动态联编的条件是通过指针或引用来调用虚函数，按上面代码的方式来解析：

    情况 ① 由于是非指针非引用的形式，所以编译器采用了静态联编，提前绑定了所有函数的地址，那么就不存在寻址的过程，程序正常运行；

    情况 ② 使用指针来调用虚函数`virFunc()`，满足动态联编条件，但由于 `memset()` 将虚表指针都置 0 了，无法通过虚表指针定位虚函数表，也就取不到虚函数地址，导致崩溃。

    情况 ③ 使用指针来调用普通函数`func()`，不满足动态联编条件，走静态联编，程序正常运行。

    情况 ④ 同情况 ② 一样，`delete p` 时调用的虚析构函数也要通过虚表指针查虚函数表，而虚表指针已被置 0，查找不到析构函数地址，导致崩溃。

## 总结

1. 静态联编把函数地址写死在指令里（或编译器已知）。动态联编把地址放进对象的 `vtable`，运行时通过 `vptr` 间接取址调用，这一层间接，换来了多态的灵活性，也带来了空间（`vptr/vtable`）和时间（间接调用、无法内联）的代价。
2. 只有通过指针或引用调用虚函数才会触发动态联编。
3. 构造函数中调用虚函数不会发生动态联编（此时派生类还未构造完成）。
4. 虚函数 + 默认参数：默认参数是静态联编的，只有函数体是动态联编，容易踩坑。
5. 虚析构函数：用基类指针 `delete` 派生类对象时，必须把析构函数声明为 `virtual`，否则是静态联编，会导致派生类析构不被调用。
