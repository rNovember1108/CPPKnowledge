# 模板

## 模板的概念

模板是一种参数化多态性的工具，可以为逻辑功能相同而类型不同的程序提供代码共享的机制。由于 C++ 程序结构的主要构件是类和函数，所以在 C++ 中，模板被分为函数模板和类模板。模板并非一个实实在在的函数或类，仅仅是函数或类的描述，模板运算对象的类型不是实际的数据类型，而是一种参数化的类型（又称为类属类型）。带类属参数的函数叫做**函数模板**，带类属参数的类叫做**类模板**。

### 函数模板

```
template<typename T1,typename T2,...>
返回值类型 函数名(参数列表){}

template <typename T>
T Add(T a, T b)
{
    return a + b;
}
```

### 类模板

```
template<typename T1,typename T2,...>
class 类模板名
{ ... }；

template<typename T>
class A
{
public:
    A(T a)
    {
        num = a;
    }

    void print()
    {
        cout << "A::num:" << num << endl;
    }

    T num;
};
```

### 模板参数

模板参数分为**类型模板参数**和**非类型模板参数**。

1. 类型模板参数是最常用的模板参数，使用关键字 `class` 或 `typename` 声明。代表一个未知的类型，在模板实例化时被具体的类型（如 `int`、`std::string`、自定义类）替换。用于实现泛型容器（如 `std::vector<T>`）、泛型算法等。注意：`class` 和 `typename` 在这里完全等价，只是历史习惯不同。
2. 非类型模板参数代表一个具体的值，而不是类型。这个值必须是编译期常量，将常量值作为模板参数，用于编译期计算、数组大小、编译期策略配置等。C++20 前后差异大，但基本原则是必须是整型（如 `int`、`char`、`size_t`）、枚举、指针/引用（C++20前）或字面量类（C++20后）。

```
template<typename T, int N = 10>
void fun(T t)
{
    std::cout << t + N << std::endl;
}
```
如上代码所示，`T` 是一个类型模板参数，实例化时由用户指定具体的类型。`N` 是一个非类型模板参数，是一个 `int` 型的编译期常量，默认值为 `10`。非类型模板参数可以有默认值，也可以没有默认值，规则跟函数参数默认值相同。如果没有默认值，在实例化模板时，你必须为没有默认值的非类型参数提供一个编译期常量实参。

## 模板的实例化

模板的实例化指函数模板（类模板）生成模板函数（模板类）的过程。

1. 对于函数模板而言，模板实例化之后，会生成一个真正的函数（编译器会根据实参类型生成具体函数，包含函数体代码）。
2. 对于类模板而言，实例化对象只是完成了类的定义（包括：确定类大小，确定成员偏移量，确定虚函数表（若有）），但成员函数不会立即生成，需要等到每个函数被调用时才会生成相应的成员函数代码。

模板的实例化分为**隐式实例化**和**显式实例化**。

### 隐式实例化

这是相对于模板显式实例化而言。在使用模板函数和模板类时，不存在指定类型的模板函数和模板类的实体时，由编译器根据指定类型参数隐式生成模板函数或者模板类的实体称之为模板的隐式实例化。

#### 函数模板隐式实例化

函数模板隐式实例化指的是在发生函数调用的时候，如果没有发现相匹配的函数存在，编译器就会寻找同名函数模板，如果可以成功进行参数类型推演，就对函数模板进行实例化。

```
template <typename T>
T Add(T a, T b)
{
    return a + b;
}

int main()
{
    int c = Add(1, 3);  // 函数实例化，此时生成了函数体代码
    int d = Add<int>(1, 3);
}
```

无论是 `Add(1, 3)` 还是 `Add<int>(1, 3)`，它们都没有使用显式实例化语法（`template ...` 声明），编译器都是在使用自动生成的函数实体。所以从"实例化方式"来看，两者完全一样，都属于隐式实例化。但两者的模板参数推导方式不同，前者叫做**隐式调用（隐式类型推导）**，编译器根据实参 `1` 和 `3` 都是 `int`，自动推导出 `T = int`。后者叫做**显式调用（显式指定类型）**，程序员用 `<int>` 明确告诉编译器 `T = int`，编译器不再自动推导。

#### 类模板隐式实例化

类模板隐式实例化指的是在使用模板类时才将模板实例化。

```
template<typename T>
class A
{
public:
    A(T a)
    {
        num = a;
    }

    void print()
    {
        std::cout << "A::num:" << num <<std::endl;
    }

    T num;
};

int main()
{
    A<int> a(10); // 第一步：类实例化，此时只生成了类定义
    a.print(); // 第二步：成员函数调用，此时才生成了成员函数代码

    // A b(5); // C++ 17之后引入CTAD新特性可以使用，此标准之前会报错
    // b.print(); 

    return 0;
}
```

在C++ 17之前，类模板的隐式实例化，只支持显式调用（显式指定类型），即需要程序员手动指定类型参数，如上述代码中的 `A<int> a(10)`。不支持隐式调用（隐式类型推导），即自动推导类型参数，如上述代码中的 `A b(5)`，程序编译时会报错。但在C++ 17之后，引入了一个新特性（CTAD），使得代码能够正常运行，详细解释本文后续章节会再做介绍。

### 显式实例化

显式实例化强制生成模板代码，在不发生函数调用的时候将函数模板实例化，或者在不使用类模板的时候将类模板实例化。

#### 函数模板显式实例化

对于函数模板而言，不管是否发生函数调用，都可以通过显式实例化声明将函数模板实例化，格式为：

```
template [函数返回类型] [函数模板名]<实际类型列表>(函数参数列表)
如：template void func<int>(const int&);
```

#### 类模板显式实例化

对于类模板而言，不管是否生成一个模板类的对象，都可以直接通过显式实例化声明将类模板实例化，格式为：

```
template class [类模板名]<实际类型列表>
如：template class Test<int>;
```

### 外部实例化

为了防止在多个源文件（.cpp）文件中都显式实例化相同的函数模板和类模板，引发重复定义错误，C++11 提出了**外部实例化**，用来避免这一情况的发生。外部实例化只需要在任意一个源文件（.cpp）文件里显式实例化一次，而在其他源文件（.cpp）文件中使用 `extern template ...` 来声明，告诉编译器不在此次生成代码，去别的地方查找。

```
template class A<float>;    // 某一个.cpp文件写，编译器遇到这段代码就直接实例化出来一个A<float>
extern template class A<float>; // 其他所有.cpp文件都这么写，去别处找定义代码
```

使用外部实例化的好处有：
1. 减少编译时间：避免在多个 .cpp 中重复实例化同一模板类型。
2. 减少二进制体积：同一模板类型的代码只在 .obj 中出现一次。
3. 隐藏模板实现：配合显式实例化，将模板定义和实现分离到 .cpp。
4. 预编译常用类型：在库中预生成 `std::vector<int>`、`std::string` 等常用模板。

`extern` 关键字在这里的含义和普通函数/变量的 `extern` 一致：
- 作用：不会在本文件中生成一个 `extern` 后边所表示的模板的实例化版本代码。
- 目的：告诉编译器，在其他的源文件（.cpp）中已经有了一个该模板的实例化版本，不要重复生成。

**注意：外部实例化声明必须配合某处的显式实例化定义，否则链接时会报"未找到符号"错误。`extern template` 是 C++11 引入的特性，C++98/03 不支持。**

### 实例化方式的优缺点

隐式实例化虽然使用方便，但在大型项目中会带来一系列不容忽视的问题：

1. 编译时间膨胀，由于模板的定义通常都在头文件里，每个包含了该头文件的 .cpp 文件（翻译单元），只要使用了这个模板，编译器就会各自独立地生成一份该类型的完整代码。如果有 50 个 .cpp 文件都用了 `std::vector<int>`，编译器就会重复生成 50 次几乎完全相同的机器码。这不仅让编译变慢，链接器还需要花大量时间去剔除这些冗余的重复定义（ODR 合并），导致链接时间也显著增加。
2. 二进制体积可能增大，虽然链接器会做合并，但编译器在生成和优化时，是分模块（每个 .obj 文件）独立进行的，编译器无法跨 .obj 文件进行内联或深度优化。这种“各自为政”的编译方式，加上重复的调试信息，最终可能导致最终生成的可执行文件或库的体积比预期要大。
3. 无法将模板实现封装在 .cpp 中，隐式实例化要求模板的完整定义（包括所有成员函数的实现）在实例化时必须可见，这就迫使你把所有实现细节都写在头文件里。这不仅暴露了商业核心算法的源码，也增加了模块间的编译依赖。只要修改了模板的一行实现代码，所有包含它的 .cpp 文件都需要重新编译，这在大型项目中代价极高。
4. 难以控制错误信息的触发位置，你在使用一个复杂的库（如Boost）时，如果隐式实例化了一个类型，而该类型不支持模板内部的某个操作，错误信息会在你调用该操作的地方才被触发，而不是在类实例化的地方。这会导致编译器输出长达数页的模板堆栈错误，错误位置往往深埋在库的实现细节里，对于开发者来说非常不友好，难以定位自己代码的问题。
5. 静态成员初始化时机复杂，如果类模板有静态成员变量，隐式实例化会导致静态成员的定义和初始化行为变得不那么直观，容易在不注意时导致链接错误（未解析的外部符号），因为静态成员的定义通常需要放在 .cpp 中，但模板代码又放在 .h 中，两者存在矛盾。

总结来说，隐式实例化最大的“缺点”，就是它把“何时、何地生成代码”的主动权完全交给了编译器，这种“按需生成、随处生成”的模式，在大规模工程中会导致严重的编译性能瓶颈和代码膨胀。所以，在实际工程中，标准的做法通常是“默认用隐式，瓶颈用显式”：平时开发用隐式实例化保持灵活性；当发现某个模板类型被广泛使用、导致编译变慢时，就用 `extern template`（外部实例化声明）配合 .cpp 里的显式实例化来优化。

## 模板的使用

1. 对函数模板的使用而言，分为两种调用方式，一种是显式模板实参调用（显式调用），一种是隐式模板实参调用（隐式调用）。
2. 对于类模板的使用而言，在 C++17 之前，没有隐式模板实参调用和显式模板实参调用的说法，因为类模板的使用必须显式指明模板实参。但在 C++17 之后，引入了一个新特性（CTAD），一定程度上打破了"类模板必须显式指定"的规则，新特性后续只要求必须确定类模板的类型，但编译器可以帮你推导。

### 隐式模板实参调用

在发生函数模板的调用时，不显式给出模板参数而经过参数推演，称之为函数模板的隐式模板实参调用（隐式调用）。如：

```
template <typename T> 
void func(T t) 
{
    cout << t << endl;
}

func(5);//隐式模板实参调用
```

### 显式模板实参调用

在发生函数模板的调用时，显式给出模板参数而不需要经过参数推演，称之为函数模板的显式模板实参调用（显式调用），显式模板实参调用在参数推演不成功的情况下是有必要的。

```
template <typename T>
T Max(const T& t1, const T& t2)
{
    return (t1 > t2) ? t1 : t2;
}

std::cout << Max<double>(1.0, 2.0)<< std::endl; // 显式模板实参调用

// std::cout<<Max(5, 'a')<< std::endl; // 无法通过编译，入参两种不同类型，Max自动推导失败
std::cout << Max<int>(5, 'a') << std::endl; //显式调用，强制指定int类型，通过编译
```

### C++17 的类模板实参推导新特性（CTAD）

上面讲过在 C++17 之前，类模板的使用必须显式指明模板实参，不能隐式推导。还是看之前的代码，将编译器改为使用C++17，发现可以成功编译。这就是 CTAD 的功劳，它一定程度上打破了"类模板必须显式指定"的规则。但仍要注意：

1. CTAD 是 C++17 才有的特性，不是所有编译器都支持（需要 C++17 以上）。
2. CTAD 依赖构造函数实参推导，如果没有构造函数或构造函数无法推导，仍然必须显式指定。
3. CTAD 主要用于简化代码，底层仍然是确定了具体类型 `A<int>` 并按隐式实例化规则生成代码。

所以，即使有 CTAD，严格来说类模板仍然需要确定具体类型，只是编译器帮忙推导了而已。如下代码所示：

```
template<typename T>
class A
{
public:
    A(T a)
    {
        num = a;
    }

    void print()
    {
        std::cout << "A::num:" << num <<std::endl;
    }

    T num;
};

int main()
{
    A a(5); // C++ 17之后引入CTAD新特性可以使用，标准之前会报错
    // A b;    // 没有构造函数入参，无法推导模板参数
    return 0;
}
```

## 模板的特化

模板特化不同于模板的实例化，模板参数在某种特定类型下的具体实现称为模板特化（显式具体化）。模板特化有时也称之为模板的具体化，分别有**函数模板特化**和**类模板特化**，特化又分为**全特化**与**偏特化(部分特化)**。

模板偏特化是模板特化的一种特殊情况，指显式指定部分模板参数而非全部模板参数，或者指定模板参数的部分特性而非全部特性，也称为模板部分特化。与模板偏特化相对的是模板全特化，指对所有模板参数进行特化。模板全特化与模板偏特化共同组成模板特化。

### 函数模板特化

#### 函数模板全特化

函数模板特化是在通用的函数模板无法适配所有类型时，为特定类型提供定制实现。

```
#include <iostream>
using namespace std;

class Test
{
public:
    Test(int a) { num = a; }
    int num;
};


// 函数模板Max，用于比较两个类型参数T的大小并返回较大的那个
template<typename T> T Max(T t1, T t2)
{
    return (t1 > t2) ? t1 : t2;
}

// 函数模板Max全特化，用于比较两个自定义对象里数字的大小并返回较大的那个
template<> Test Max<Test>(Test s1, Test s2)
{
    return (s1.num > s2.num) ? s1 : s2;
}

int main()
{
    //调用实例：int Max<int>(int, int)
    int i = Max(10, 5);

    // 调用显式特化：Test Max<Test>(Test, Test)
    Test a(10), b(5);
    Test test = Max<Test>(a, b);

    cout << "i:" << i << endl;
    cout << "test:" << test.num << endl;
}
```

在函数模板特化定义中，使用关键字 `template` 和一对尖括号 `<>`，然后是函数模板特化的定义。该定义指出了模板名、被用来特化模板的模板实参，以及函数参数表和函数体。在上面的程序中，如果不给出函数模板 `Max<T>` 在 `T` 为 `Test` 时的特化版本，那么在比较两个对象中成员 `num` 的大小时，会调用默认的函数模板 `Max<T>`，而不是特化的版本，导致报错（自定义对象不能比较大小）。

另外，除了定义函数模板特化版本外，还可以直接给出模板函数在特定类型下的重载形式（普通函数）。使用函数重载可以实现函数模板特化的功能，也可以避免函数模板的特定实例的失效。例如，把上面的模板特化可以改成如下重载函数。

```
// 重载函数版本代替特化版本
Test Max(Test s1, Test s2) 
{
    return (s1.num > s2.num) ? s1 : s2;
}

// 调用时，去除显式指定模板参数，直接调用普通函数即可。
Test test = Max(a, b);
```

程序运行结果和使用函数模板特化相同。但是，使用普通函数重载和使用模板特化还是有不同之处，主要表现在如下三个方面： 

1. 优先选择，如果一个非模板函数和同名模板函数同时存在，若参数类型和非模板函数完全相同，优先调用非模板函数；否则调用模板函数实例化。
2. 如果使用普通重载函数，那么不管是否发生实际的函数调用，都会在目标文件中生成该函数的二进制代码。而如果使用模板的特化版本，除非发生函数调用，否则不会在目标文件中包含特化模板函数的二进制代码。这符合函数模板的“惰性实例化”准则。
3. 如果使用普通重载函数，那么在分离编译模式下，应该在各个源文件中包含重载函数的申明，否则在某些源文件中就会使用模板函数，而不是重载函数。

#### 函数模板偏特化

函数模板是不允许偏特化的，是语言设计上的有意为之，核心原因在于：函数模板已经有“重载”这个更强大、更安全的机制来实现同样的目的，引入偏特化反而会带来语法歧义和违反直觉的行为。下面的声明会编译报错，“func”: 非法使用显式模板参数。

```
template <class T1, class T2>
void func(T1, T2) {}

// 偏特化模板函数（编译错误）
template <class T2>
void func<int, T2>(int, T2) {}
```

但函数允许重载，声明另一个函数模板即可替代偏特化的需要

```
template <class T1, class T2>
void func(T1, T2) {}

// 函数重载实现"固定第一个参数"的效果
template <class T2>
void func(int, T2) {}
```

### 类模板特化

#### 类模板全特化

类模板全特化类似于函数模板的全特化，即类模板参数在某种特定类型下的具体实现。

```
template<class T1, class T2>
class Test
{
public:
    Test(T1 a, T2 b) :t1(a), t2(b)
    {
        cout << "模板实例化" << endl;
    }
private:
    T1 t1;
    T2 t2;
};

//模板全特化
template<>
class Test<int, int>
{
public:
    Test(int a, int b) :t1(a), t2(b)
    {
        cout << "模板全特化" << endl;
    }
private:
    int t1;
    int t2;
};

int main()
{
    Test<double, double> a(1.2, 3.4);
    Test b(1, 2); //  C++17之后使用
    return 0;
}
```

#### 类模板偏特化

1. 偏特化部分模板参数

    ```
    // 模板偏特化部分模板参数
    template<class T>
    class Test<int, T>
    {
    public:
        Test(int a, T b) :t1(a), t2(b)
        {
            cout << "模板偏特化部分模板参数" << endl;
        }
    private:
        int t1;
        T t2;
    };

    // C++17之后使用
    Test b(1, 2);
    ```

2. 偏特化模板参数特性，包括指针/引用、CV限定符、数组、容器（模板模板参数）、元函数（条件匹配如：`enable_if`）

    ```
    // 两个参数偏特化为引用类型
    template <typename T1, typename T2>
    class Test <T1&, T2&>
    {
    public:
        Test(const T1& a, const T2& b) : t1(a), t2(b)
        {
            cout << "模板偏特化为引用类型" << endl;
        }
    private:
        const T1& t1;
        const T2& t2;
    };

    // 方法1：直接使用显式调用命中偏特化
    Test<int&, int&> b(1, 2);

    // 方法2：添加 C++17 推导指引,将左值推导为左值引用类型
    template <typename T1, typename T2>
    Test(T1, T2) -> Test<T1&, T2&>;

    // 方法2：使用自动推导模板参数类型，C++17之前，会报错
    Test b(1, 2);
    ```

## 共存和编译机制

当函数模板和函数重载共存时，编译器会根据以下规则来确定使用哪个函数：

1. **精确匹配**：如果有一个非模板函数与调用完全匹配（参数类型和数量都相同），那么编译器会优先选择这个函数。
2. **模板推导**：如果没有精确匹配的非模板函数，编译器会尝试使用函数模板，并通过模板推导来确定模板参数的类型。
3. **错误处理**：如果模板推导失败或产生歧义，编译器会报错。

## 模板的编译

在工作中遇到一个有趣的问题，现有一个通用模板类如下：

```
template <typename T>
class Test
{
public:
    static int s_count;   // 跨 DLL 若不导出，可能每个模块各一份
};
template <typename T> int Test<T>::s_count = 0;
```

当 `Test` 类需要多个 dll 使用时，同一份模板代码在 MSVC 和 MinGW（基于 GCC）两个编译器下会出现不同的表现：

- **MSVC**：对模板实例采用弱符号（COMDAT）处理，不显式导出时通常也能编译通过、看似正常运行。但要注意，这**并不保证跨 DLL 使用的是同一个实例**——由于 Windows PE 不做跨模块符号合并，模板类的 `static` 成员（乃至单例对象）很可能每个 DLL/EXE 各持有一份，从而埋下"状态不唯一"的隐蔽 bug。
- **MinGW/GCC**：在 PE 平台默认不导出模板实例的符号，也没有 MSVC 那套宽松的弱符号容错，跨 DLL 时会直接表现为符号无法解析（链接失败），问题暴露得更早、更硬。

可见两者的差异本质是**对模板实例的默认符号可见性与导出策略不同**，而非"谁能识别、谁不能识别"。可靠且通用的解决办法对两者是一致的：在**某一个** DLL 中显式实例化并用导出宏导出该实例，其余模块导入同一符号，从而保证实例唯一。

```
// .h文件（被库自身和所有使用方共同包含）
#if defined(_WIN32)
    #ifdef MYLIB_BUILD_DLL
        #define MYLIB_API __declspec(dllexport)
    #else
        #define MYLIB_API __declspec(dllimport)
    #endif
#else
    #if defined(__GNUC__) || defined(__clang__)
        #define MYLIB_API __attribute__((visibility("default")))
    #else
        #define MYLIB_API
    #endif
#endif

// 外部实例化声明：只声明不生成代码，告诉每个包含此头文件的翻译单元
// “Test<int> 的实例在别处定义，不要自行生成”。
// 对使用方而言，此时 MYLIB_BUILD_DLL 未定义，MYLIB_API 展开为 dllimport，即导入该实例。
extern template class MYLIB_API Test<int>;

// .cpp文件（仅库自身的某一个源文件，全程序唯一一处定义）
// 显式实例化定义：真正生成 Test<int> 的实例代码与静态成员，只能有一处。
// 编译该库时 MYLIB_BUILD_DLL 已定义，MYLIB_API 展开为 dllexport，即导出该实例。
template class MYLIB_API Test<int>;
```

## 总结

1. C++17之前类模板的隐式实例化只支持显式调用，在C++17之后因为新特性 CTAD 的原因，底层能够利用隐式调用规则为我们自动生成代码。CTAD 让类模板的调用方式从显式变为隐式，但实例化方式始终是隐式实例化。但需注意CTAD 并非万能，是有先决条件的。
2. 模板函数是不支持偏特化的，可以使用普通重载函数代替。不论使用什么操作系统平台与编译器，为了确保模板跨DLL最终使用同一实例，请采用导入/导出宏+外部实例化（`extern template class`）+显式实例化（`template class`）的方式来达到你的目的。
